## 1. 结论摘要

仓库已经具备有说服力的本地工程证据，但**尚不适合直接公开发布**。当前代码、模型、运行数据和密钥隔离状况良好；主要阻塞来自发布身份和版权尚未决定，以及“源码仓库可运行”尚未转化为“干净环境中可安装、可构建、可由公共 CI 复现”。

本次审计把问题分成三类：

- **发布前强制解决**：项目许可证与内容授权、第三方许可证/归属清单、公开身份与未来 Git 作者、是否保留历史作者、公开仓库策略、可分发包的数据文件边界、干净环境构建/安装证据、公共发布前最终历史敏感信息扫描。
- **重要但可在首次公开后补充**：README 首页重构、中英文摘要、架构图、截图或 GIF、核心依赖锁定策略和更多平台的 CI 证据。
- **可选增强**：真人配音、公开 Issue/项目看板、Gitee 镜像、Tag/Release、PyPI 发布。它们都不是证明当前作品价值的必要条件。

M0～M5 的功能边界不因本审计重新打开。M6-P1 尚未开始，远程仓库也没有创建。

- 52 个提交中的全部路径；

- `pyproject.toml` 没有 `authors`、`maintainers`、`license`、项目 URL、分类器或关键词；

- 代码、测试、病例文本、世界观与文档的作者/版权归属没有在仓库内明确；
- 没有说明 AI 辅助开发、素材来源或贡献规则。

由于大量验证记录引用精确提交哈希，改写 52 个提交的作者会改变整条历史的提交 ID，并要求同步修复所有证据引用。审计建议默认保留既有历史、把 `wyd` 解释为开发期署名，并从未来提交开始使用用户确认的公开身份；如果用户坚持改写，必须在任何远程发布前另行授权和执行完整引用迁移。

## 5. 招聘者阅读体验

### 5.1 30 秒与 3 分钟审计

当前 README 的首屏可以看出“道家志怪智能 NPC”和 M5 已完成，但紧接着是一份超过 60 项的实现清单。招聘者能确认工程量，却很难在 30 秒内回答：

1. 这个项目解决了什么独特问题？
2. 我应该先运行哪个命令？
3. 最能证明能力的三项结果是什么？
4. 哪些结果是离线工程事实，哪些只是单次模型案例？

README 约 297 行、23 KB。运行命令、MCP、DeepSeek、历史实验和限制都集中在同一页；大量真实停止记录和负结果很有价值，但会淹没主线。当前没有被 Git 跟踪的架构图、截图、GIF 或视频，也没有英文摘要。

### 5.2 推荐的两层结构

P2 建议把 README 改成“首页摘要 + 证据索引”：

- 首屏：一句话定位、三张能力证据卡、60 秒无 Key 启动、单张架构图；
- 第二屏：三病例与跨案体验、Agent/MCP 安全路径、真实正负结果边界；
- 其后：两个岗位各自入口、演示链接、测试与限制；
- 详细实验、停止记录和历史审计保留原文件，通过 `docs/INDEX.md` 按“核心架构 / 游戏产品 / 真实实验 / 负结果 / 历史检查点”导航，不删除历史。

英文摘要建议限制为首页的 5～8 行和关键术语，不必把全部实验文档双语化。架构图和演示媒体应在 P2 单独制作并核对版权、脱敏和可访问性。

## 6. 可复现性与发布工程条件

### 6.1 已有优势

- 核心安装没有把 BGE、CUDA 或大型 ML 依赖作为强制依赖；
- manual/Fake/无 LLM 路径不需要 API Key；
- Windows Python 3.12 已有真实安装、CLI、stdio 子进程、重启恢复和 482 项测试证据；
- 本地 Embedding 使用单独的 Windows/CUDA 精确依赖清单；
- `xuanyi-play`、`xuanyi-mcp-stdio` 和 `xuanyi-m5-acceptance` 已有明确职责边界。

### 6.2 当前缺口

本轮没有构建 wheel/sdist。现状只能说明 `pyproject.toml` 提供了 setuptools 构建声明，不能说明产物实际可安装。更重要的是：

- setuptools 当前只发现 `src` 下的 Python 包，没有声明 `data/cases`、`data/campaign` 和评测数据为 package data；
- 多个命令通过“源码文件向上寻找仓库根目录”读取 `data/`；
- 因此即使 wheel 能构建，也不能据此声称脱离源码仓库后仍能完整游玩或评测；
- 当前 `.venv` 没有安装 `build` 和 `wheel`，P0 按范围没有安装或试构建；
- 没有核心最小依赖锁或 constraints 文件；只有本地 BGE 的 Windows/CUDA 精确清单；
- 没有 `.github/workflows` 或其他 CI 配置；
- `requires-python >=3.11`，但真实发布证据集中在 Windows Python 3.12，Linux、macOS、Python 3.11/3.13 均未验证。

P1 必须先选择发布形态：如果只承诺“clone 后运行”，README 应明确；如果承诺 wheel 安装，需要把病例/Campaign 作为受控 package data 或资源包，并在不依赖仓库根目录的全新环境验证。

### 6.3 建议的公共 CI 边界

P1 建议建立以下最小矩阵，但本轮不创建：

1. Windows Python 3.12：作为当前已验证平台的强制门禁；
2. Ubuntu Python 3.11/3.12：验证核心可移植性；在通过前标记为实验支持；
3. 构建 wheel/sdist、检查元数据，并从产物安装后运行 CLI `--help` 与无 Key smoke；
4. 运行不需要模型/API 的全量测试、MCP 进程内与 stdio、Fake/no-LLM、事件重放；
5. 检查敏感信息、禁止跟踪路径、Git diff 和许可证清单。

公共 CI 不得：

- 下载或加载 BGE-M3；
- 请求 DeepSeek `/models`、Chat 或任何 Embedding API；
-读取真实 `.env` 或 secret；
-运行付费 Pilot、真实模型 smoke 或需要私有原始结果的验收分支；
-把 Windows/CUDA 真实证据泛化为全平台生产支持。

依赖安装本身通常需要访问包索引；应把“安装阶段允许下载固定依赖”和“测试阶段禁止访问模型/API”分开记录，不能含糊声称整个 CI 全程无网络。
