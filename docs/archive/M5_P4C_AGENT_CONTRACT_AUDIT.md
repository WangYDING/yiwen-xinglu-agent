# M5-P4c Agent 工具契约与拒绝恢复离线审计

## 结论

M5-P4c 是一次通用 Agent 接口与恢复能力改进，不是针对灰灶答案的 Prompt 调参。三个病例、8 步上限、V0 Prompt `v0.2.1`、病例真值、评分、Campaign 规则和 `fixed_v0` 诊断就绪策略均未改变。本阶段没有调用 DeepSeek、BGE、Embedding API 或其他网络服务。

M5-P4b 的历史结论保持不变：工程与规则安全通过，灰灶行为未完成，月井未运行，旧纸伞到灰灶的公开前史承接已验证。原始结果仍位于 Git 忽略目录，SHA-256 仍为 `EFDC6B37692CAA117B352DD199B52AAFF20D765945E5C8FB585994453B712C2B`。本次离线修复不能回写为 P4b 成功。

## 修改前的证据

### 工具契约校验缺口

- `AgentAction.tool_call.arguments` 是供应商输出边界上的通用字典；因此结构化 JSON `question_patient(target_id=...)` 可以通过外层 `AgentAction` Schema。
- 准确调查参数实际上是唯一字段 `investigation_id`。P4b 中第 2、3 步直到 `MultiCaseEpisodeService`/`V0ToolExecutor` 执行阶段才以 `invalid_tool_arguments` 被拒绝。
- 规则层安全有效：这两步没有领域事件、修订或 CampaignEvent。但错误进入应用执行层太晚，也没有消费既有的一次修复额度。

### 拒绝反馈缺口

- 修改前，Runner 把不同规则拒绝压缩为通用 `SAFE_REJECTION_FEEDBACK` 文本。
- 反馈没有稳定 `error_code`、公开错误说明、`can_submit_diagnosis`，也没有刷新后的“准确工具名 + `investigation_id`”列表。
- P4b 第 6～8 步在 `diagnosis_not_ready` 后重复同一诊断，证明模型没有获得足够的程序化恢复信息；规则层仍然正确地保持零写入。

## P4b 行为的分层解释

### 已有事实

- 第 2、3 步均输出 `question_patient(target_id=cook_shen)`，外层 JSON 合法，工具执行拒绝。
- 第 5 步使用 `respond` 解释并口头给出诊断；口头说明没有提交诊断。
- 第 6～8 步重复提交同一诊断，均被 `diagnosis_not_ready` 拒绝。

### 工程归因

- 第 2、3 步同时暴露模型参数选择错误和公开行动契约校验过晚；后者属于可修复接口缺口。
- 第 6～8 步首先是模型过早诊断，其后的重复行为受通用反馈信息不足影响；这属于拒绝恢复接口缺口与模型策略问题的组合。
- 第 5 步解释性 `respond` 是模型步骤效率和行动策略问题。本阶段不禁止 `respond`，也不通过答案式规则强迫参考轨迹。

### 推断边界

新的离线测试证明通用修复信息足以让脚本化模型纠正为合法公开行动，但不能证明真实 DeepSeek 必然会正确恢复，也不能证明它会减少 `respond` 或在 8 步内完成病例。该行为结论只能由另行授权的 P4d 真实验证产生。

## 修改后的处理流程

修改前：

`AgentAction Schema → 应用服务/工具执行器 → 规则拒绝 → 通用文本反馈 → 下一步模型调用`

修改后：

`AgentAction Schema → 当前公开行动契约 → 首次不合同时使用一次 action_contract_repair → 契约合法后才提交应用服务 → 规则层最终裁决 → 结构化安全反馈`

公开行动契约统一适用于三个病例：

- 调查只允许准确的 `investigation_id`，并核对工具类型与当前公开调查类型；
- 诊断只允许公开候选和已发现证据，并尊重公开的 `can_submit_diagnosis`；
- 处置只允许当前公开处置 ID；
- 额外字段、未知 ID、类型不匹配和未发现证据在状态服务之前拒绝；
- 第一次契约错误可使用既有的一次修复额度，记录为 `action_contract_repair`，与 JSON `format_repair` 分开；
- 修复后仍不合法时使用确定性非工具降级，不进行第三次模型调用；
- 契约合法的正常动作仍只调用模型一次；
- 确定性规则引擎继续拥有最终裁决权，契约层不写状态、不生成事件，也不复制病例规则。

## 结构化安全反馈

反馈严格包含：稳定 `error_code`、安全 `public_message`、`can_submit_diagnosis`、刷新后的公开调查（准确工具名、`investigation_id`、公开说明）、公开诊断候选、当前公开处置候选，以及“口头描述不等于提交诊断”的固定声明。

反馈不包含原始异常、路径、病例根因、正确诊断/处置、评分、未发现线索、隐藏门槛、语义记忆、完整 Prompt 或密钥。修复请求不会回显原始错误模型输出。

## 历史兼容边界

冻结的 P0 Fake 评测与真实 Pilot 脱敏轨迹仍使用提交时的历史执行语义，以保证历史结果可复核而不被新恢复步骤重新解释。该兼容开关是评测器内部的只读历史回放边界，不是产品模式、CLI 选项或真实 Agent 逃逸路径。当前 `ModeAwareEpisodeRunner` 和新的产品 V0 Episode 默认始终启用公开行动契约。

## 尚未解决的模型策略问题

- 真实模型是否会在收到结构化反馈后选择有效调查，尚未验证。
- 解释性 `respond` 仍可能占用 8 步预算；本阶段只记录，不硬编码禁止。
- 即使参数和恢复正确，模型仍可能选择低效调查、错误诊断或错误处置。
- P4d 若获授权，只能验证新的真实恢复行为；不得改写 P4b 的负结果。
