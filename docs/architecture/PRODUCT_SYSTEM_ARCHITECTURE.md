# 《问道医途》产品系统架构

> 状态：架构边界冻结（2026-08-11）
>
> 本文描述目标产品的权威边界与数据流，不表示所列模块都已实现。成熟度以 [`M5_PRODUCT_GAP_AUDIT.md`](../archive/M5_PRODUCT_GAP_AUDIT.md) 为准；配置枚举、Pydantic 空壳或规划文档都不能作为功能完成证据。

## 总体原则

- 玩家亲自调查、诊断和处置；导师 Agent 不代替玩家操作病例。
- LLM 负责角色语言、受约束教学表达和建议，不拥有关键状态写权限。
- 病例真相、行动合法性、评分、成长、关系、课程、考试、权限和传承均由确定性规则决定。
- 所有状态变化先形成严格领域命令，再由规则验证并产生可重放领域事件。
- 模型只看权限过滤后的公开视图；隐藏真值、未发现线索和内部门槛不得进入 Prompt。
- 结构化可信历史是正式能力；语义向量记忆继续关闭，不进入 Prompt、行动或状态路径。

## 模块清单与权威边界

### 1. 世界与角色

| 项目 | 定义 |
|---|---|
| 输入 | 版本化世界观、导师人格、角色公开资料、架空医术与内容安全规则 |
| 输出 | 可公开的角色设定、叙事约束、导师表达边界 |
| 权威状态 | 版本化内容资源；不由运行时模型改写 |
| LLM 权限 | 在固定人设和安全范围内组织语言，不得新增会影响规则的世界事实 |
| 确定性规则 | 内容版本、公开/隐藏字段、现实医疗禁区、角色身份 |
| 依赖 | 无；为病例、教学和交互层提供共同语境 |

R2 已以版本化可信资源提供“玄医先生”统一人格，并在旧纸伞教学闭环中通过安全公开视图使用；运行时模型不能修改人物资源。

### 2. 玩家模型

| 项目 | 定义 |
|---|---|
| 输入 | 已提交的病例、教学、考试、关系、权限和承诺事件 |
| 输出 | 玩家公开档案、能力视图、关系视图、阶段、权限和可信历史范围 |
| 权威状态 | R1 的跨 Episode `ApprenticeshipState`；病例 Session 中的 `PlayerState` 技能/关系字段只作兼容快照或执行输入 |
| LLM 权限 | 只读权限过滤视图；可提出评价或建议，不能修改数值和解锁 |
| 确定性规则 | ID 隔离、修订、技能前置、增量上限、幂等和事件来源 |
| 依赖 | 病例证据、教学评价、考试结果、关系规则、权限图 |

R1 已以单一 `ApprenticeshipState` 建立正式成长更新闭环。它不会反向改变病例答案、评分、行动权限或 DoctorAgent Prompt；病例 Session 不能独立修改长期成长。R2 导师只通过公开视图和本次结构化变化读取并解释该状态。

### 3. 病例系统

| 项目 | 定义 |
|---|---|
| 输入 | 玩家提交的公开调查、诊断和处置命令 |
| 输出 | `CaseEvent`、公开观察、结局、得分和可重放会话 |
| 权威状态 | `CaseDefinition`、`CaseSessionState`、`CaseEngine` |
| LLM 权限 | 无直接写权限；历史自动解题模式只能提出 `AgentAction` |
| 确定性规则 | 真相、证据发现、技能权限、诊断就绪、处置前置、评分和结局 |
| 依赖 | 玩家技能只读快照、内容资源、存储和事件重放 |

病例是教学载体，不直接决定玩家永久成长。教学评价层只能读取已经提交的病例事件。

### 4. 导师 Agent

| 项目 | 定义 |
|---|---|
| 输入 | 导师安全上下文：公开病例状态、当前课程目标、玩家已提交行为、结构化可信历史、允许的教学动作 |
| 输出 | 角色化说明、追问、有限提示、反馈，以及结构化教学建议 |
| 权威状态 | 无；导师输出不是状态事实 |
| LLM 权限 | 选择允许的表达或提出受约束建议；不得替玩家调用病例行动，不得写成长、关系、权限或记忆 |
| 确定性规则 | 上下文过滤、输出 Schema、提示额度、可用教学动作、一次有界修复和安全降级 |
| 依赖 | 教学系统、玩家公开视图、病例公开视图、结构化历史、权限层 |

正式导师需要独立于 V0 `DoctorAgent` 的输入、输出和 Prompt。现有 DoctorAgent 自动提交病例工具，只保留为 Fake、验收和模型工程评测模式。

### 5. 教学系统

| 项目 | 定义 |
|---|---|
| 输入 | 当前课程、已提交病例事件、过程评价维度、提示使用和先前补课结果 |
| 输出 | 教学目标、允许提示、过程评价事实、补课或下一课建议 |
| 权威状态 | 版本化课程定义、教学会话和教学事件 |
| LLM 权限 | 表达规则选出的目标与评价；可在允许集合内提出教学策略建议 |
| 确定性规则 | 课程资格、提示额度、评价证据、补课条件、幂等结算 |
| 依赖 | 病例事件、玩家模型、考试系统 |

最小实现先固定一个课程和一次有界提示，不提前实现自适应改序。

### 6. 考试与晋级

| 项目 | 定义 |
|---|---|
| 输入 | 课程完成记录、能力证据、关系与承诺门槛、考试行动事件 |
| 输出 | 考试资格、结果、补考/补课要求和阶段变化事件 |
| 权威状态 | 考试定义、考试会话、阶段事件 |
| LLM 权限 | 说明考试、扮演考官和表达结果；不得判定通过或改阶段 |
| 确定性规则 | 准入、题目/病例配置、通过条件、重试和晋级 |
| 依赖 | 教学、能力、关系、权限系统 |

现有 `TeachingStage` 枚举不代表考试或晋级已经实现。

### 7. 三维师徒关系

| 项目 | 定义 |
|---|---|
| 输入 | 可验证互动、守约/违规、风险承担、学习表现与长期一致性事件 |
| 输出 | 亲近、信任、认可的独立变化事件和公开解释 |
| 权威状态 | 三维关系状态及关系事件日志 |
| LLM 权限 | 表达态度和解释变化；不能直接增减数值 |
| 确定性规则 | 事件到维度的映射、单次上限、重复结算、下限/上限和传承读取条件 |
| 依赖 | 病例、教学、考试、承诺和结构化历史 |

亲近不能代替能力，认可不能代替信任，任何单一维度都不能独立开放传承。

### 8. 长期记忆

| 项目 | 定义 |
|---|---|
| 输入 | 允许列表内的已验证领域事件 |
| 输出 | 来源可追溯的结构化记忆；实验环境可额外产生派生向量 |
| 权威状态 | SQLite 权威 MemoryEvent、来源收据、生命周期和墓碑 |
| LLM 权限 | 只读权限过滤后的历史；没有记录、修改、更正或删除工具 |
| 确定性规则 | 投影、玩家隔离、幂等、冲突、更正、失效、硬删除和重建 |
| 依赖 | 领域事件、玩家作用域、AgentContextFilter |

正式产品先以结构化事件事实驱动导师反应。Dense 语义检索因真实质量门禁未通过而保持关闭；shadow 只能记录，不能注入。

### 9. 知识权限与传承

| 项目 | 定义 |
|---|---|
| 输入 | 技能、课程、考试、三维关系、公开承诺和关键历史事实 |
| 输出 | 知识/工具/术法权限事件、传承资格和最终传承决策 |
| 权威状态 | 版本化权限图、解锁/撤销事件、传承记录 |
| LLM 权限 | 解释条件、提出规则允许的仪式表达；不能授予权限 |
| 确定性规则 | 多条件门槛、前置图、来源、幂等、撤销和审计 |
| 依赖 | 玩家模型、教学、考试、关系、结构化记忆 |

现有 Campaign 知识是跨案公开连续性，不等于完整技能权限或传承系统。

### 10. 交互入口

| 项目 | 定义 |
|---|---|
| 输入 | 玩家菜单选择、文本请求和明确的确认操作 |
| 输出 | 公共状态、导师反馈、合法选项、错误码和保存结果 |
| 权威状态 | 无；入口是应用服务的薄层 |
| LLM 权限 | 仅由导师边界接入；不能让自然语言绕过结构化命令 |
| 确定性规则 | 输入规范化、玩家/会话绑定、公开选项、错误脱敏和退出恢复 |
| 依赖 | 应用服务、病例、导师、教学、玩家状态 |

当前 CLI 是可玩的正式入口；未来界面仍必须复用相同应用服务和规则。

### 11. 基础设施与持久化

| 项目 | 定义 |
|---|---|
| 输入 | 已验证领域事件和待保存的新状态 |
| 输出 | 原子 JSON 状态、SQLite 记忆、协调状态、审计日志和回放结果 |
| 权威状态 | Case/Player/Campaign JSON 与 SQLite 记忆各自的明确权威边界 |
| LLM 权限 | 无文件、数据库或网络写权限 |
| 确定性规则 | 先状态后投影、失败窗口、显式协调、修订、哈希和玩家隔离 |
| 依赖 | 所有会产生领域事件的应用服务 |

当前存储不承诺并发多进程事务或生产运维；不得用伪分布式事务掩盖故障窗口。

### 12. 评测与可观测性

| 项目 | 定义 |
|---|---|
| 输入 | EpisodeResult、领域事件、回放状态、脱敏模型用量与人工 Gold |
| 输出 | 工程、安全、行为、成本和产品体验的分层结果 |
| 权威状态 | 冻结评测契约、结果哈希和不可改写的历史记录 |
| LLM 权限 | 不生成真值和成功条件；评测器不读取模型自评作为判定 |
| 确定性规则 | 指标分母、失败类别、安全硬门槛、预算与停止条件 |
| 依赖 | 病例、Agent、存储、记忆和未来试玩协议 |

测试数量只证明回归覆盖，不能替代可玩闭环、真实模型或真人试玩成熟度。

## 端到端数据流

```text
玩家输入
  → 交互入口规范化
  → 权限过滤后的公开可用行动
  → 应用服务构造领域命令
  → 确定性病例规则验证
  → CaseEvent
  → 原子保存 CaseSession
  → 教学观察器只读取已提交事件
  → 确定性形成教学评价证据
  → 规则计算成长 / 关系 / 课程 / 考试 / 权限事件
  → 原子保存各自权威状态
  → 投影结构化可信历史
  → AgentContextFilter 构造导师安全上下文
  → 导师 LLM 生成受约束表达或建议
  → 输出校验与有界修复
  → 向玩家展示
```

MCP 是应用服务的另一入口，不是规则捷径。Fake/DoctorAgent 自动解题路径是工程评测入口，不进入正式玩家主循环。semantic shadow 位于已提交事件之后，结果立即丢弃，不连接导师 Prompt、行动或状态。

## Product Completion Plan v1 实现顺序

M0～M6 继续作为不可改写的历史工程里程碑。新的产品实现主线以 [`PRODUCT_COMPLETION_PLAN_V1.md`](../product/PRODUCT_COMPLETION_PLAN_V1.md) 为准：

1. R1：长期状态与确定性成长底座（已完成）；
2. R2：读取并解释 R1 状态的导师教学闭环（已完成）；
3. R3：三病例教学、补课与结构化记忆（已完成）；
4. R4：考试、权限与传承（已完成）；
5. R5：六病例与医馆入口（已完成）；
6. R6：产品验收与发布准备。

R1～R5 已完成；R6 正在进行离线验收。R4 的 `ExamSessionState` 保存不可修改的考试 attempt；唯一 `PermissionState` 派生阶段、资格、权限、考试认可和传承。R5 的 `ClinicService` 只组合正式服务与安全公开视图，不成为新权威状态。权限过滤先于资源读取、导师上下文和结构化记忆选择；TeachingSession/TeachingPlan 与 R1 成长权威仍保持独立。
R6 离线验收器只在隔离临时目录读取冻结包资源，并输出到显式 Git 忽略目录；它不成为产品权威，不导入付费模型或 Embedding 适配器。R6整体仍进行中。

该顺序仅调整模块依赖。R1 不包含导师 Agent、教学、考试或传承，也不得让长期成长提前参与病例执行或 Prompt；关键状态仍只由确定性规则和领域事件写入。

## 状态更新顺序

1. 从可信存储加载并校验玩家、病例、教学和 Campaign 修订。
2. 由服务端根据玩家身份构造公开视图，客户端或模型不能指定权限作用域。
3. 玩家提交严格命令；参数错误在领域执行前拒绝。
4. 规则层再次验证合法性，拒绝时事件、修订和文件字节均不变。
5. 成功动作产生连续事件，并先保存病例会话。
6. 教学、成长、关系、考试、权限和 Campaign 分别由显式协调器消费已提交事件；每个投影以稳定来源键幂等。
7. 任一后续投影失败时保留已成功的病例状态，返回明确 pending 状态，不能伪装成全部成功。
8. 所有公开反馈只从保存后的权威状态重新构建。
9. 导师表达失败不能回滚或改写已经提交的游戏事实；使用安全确定性文本降级。
10. 重放从初始状态加事件序列重建，并与磁盘终态比较。

## 实现与声明门禁

一个模块只有在以下证据匹配时才能提高成熟度：

- L1：只有契约或数据结构；不得称为“已具备功能”；
- L2：确定性规则与边界测试成立；不得称为“玩家可体验”；
- L3：进入普通玩家可操作的端到端闭环并可恢复；
- L4：具有真实模型或完整工程验证，且明确验证范围；
- L5：有预注册真人试玩和真实玩家证据。

枚举值、配置开关、空数据库表、Prompt 描述、Fake 脚本或测试数量不能单独提升成熟度。
