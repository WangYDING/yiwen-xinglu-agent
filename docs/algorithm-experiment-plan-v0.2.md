# 《面向长期交互的道医智能 NPC》算法实验方案 v0.2

## Material Passport

- **版本**：`experiment_plan_v0.2`
- **日期**：2026-08-04
- **验证状态**：P0 VERIFIED / REAL-LLM UNVERIFIED（尚未运行真实模型实验）
- **当前工程阶段**：M2a、M2b-P0 已完成，M2b-P1 待完成
- **取代范围**：取代 v0.1 的当前执行口径；v0.1 原文件保留为历史版本
- **结论边界**：不提供现实医疗能力，不把研究目标写成已经实现的结果

## 1. 当前事实与待验证事项

已经由自动化测试验证：

- 确定性病例规则、状态错误和评分；
- 安全只读上下文与结构化 `AgentAction`；
- Fake LLM 下的一次格式修复、确定性降级、最大步骤和 Episode 重放；
- 公开诊断候选可用，未知候选不能改变状态；
- 3 条供应商无关 dev 场景的参考/错误轨迹、确定性分类和安全上下文审计；
- V0、V1、V2 配置均强制启用 `AgentContextFilter`。

尚未验证：

- 任何真实模型的任务成功率、工具选择、格式稳定性或角色质量；
- 真实超时、Token、延迟和成本；
- 长期记忆、自适应教学、Reflection、MCP 或多 Agent；
- V1、V2 相对 V0 的任何效果提升。

因此，当前不能把整个 M2 标记为完成，也不能生成简历指标。

## 2. 研究问题

- **RQ1**：在相同模型、病例、工具和安全过滤下，基础向量记忆与多因素记忆/自适应教学能否提高长期任务成功率？
- **RQ2**：多因素排序能否提高关键记忆的 Precision、Recall 与 F1，并降低错误记忆率？
- **RQ3**：自适应课程能否提高课程匹配度并减少难度偏差？
- **RQ4**：在隔离合成环境中，程序化权限过滤相对仅提示词保密能降低多少泄漏风险？
- **RQ5**：能力增益带来的真实 Token、延迟和成本变化是多少？
- **RQ6**：工具失败、对抗输入和状态冲突下，系统是否仍保持合法状态和可恢复性？

## 3. 研究假设与目标

- **H1**：V2 的端到端任务成功率可能高于 V1；“绝对提升 10 个百分点”是待检验的研究目标，不是工程完成条件。
- **H2**：V2 的记忆 F1 可能高于 V1，错误或虚构记忆比例可能更低。
- **H3**：V2 的课程选择质量可能高于使用固定课程的 V0/V1。
- **H4**：隔离 A4 中，启用程序化过滤的安全配置可能比仅提示词保密对照具有更低泄漏率。H4 不比较不安全产品 V0 与安全 V1/V2。
- **H5**：V2 的真实 Token 与 P95 延迟增幅应在 Pilot 后设定可接受目标；当前不预填结果。
- **H6**：所有产品版本的关键状态非法写入和会话串扰都应为 0。

除 H6 的安全底线外，数值均为研究假设或优化目标。没有达到预期增益时，应保留并报告负结果，而不是把它解释为工程未完成。

## 4. 产品版本边界

三个产品版本共用：

- 相同基础模型和采样配置；
- 相同确定性病例引擎、工具 Schema 和最大步骤；
- 相同 `AgentAction` 与 `EpisodeResult`；
- 强制开启的 `AgentContextFilter`；
- 模型不得直接修改病例、关系、能力、权限、技能或永久记忆。

| 能力 | V0 | V1 | V2 |
|---|---|---|---|
| 上下文 | 最近 K 条消息 | 最近消息 + 长期记忆 | 最近消息 + 长期记忆 |
| 长期记忆 | 无 | 基础向量 Top-K | 多因素排序 |
| 课程 | 固定顺序 | 固定顺序 | 自适应课程 |
| Reflection | 无 | 无 | 有 |
| `AgentContextFilter` | 强制 | 强制 | 强制 |
| 结构化行动与规则工具 | 有 | 有 | 有 |

### V0：安全 Prompt-Only Fixed Curriculum

- 仅使用最近 K 条对话；
- 不读取或写入长期记忆；
- 使用固定课程；
- 使用程序化过滤后的玩家、病例和公开候选视图；
- 使用结构化工具循环、规则拒绝、有限修复和降级；
- 不进行 Reflection。

“Prompt-Only”只表示不含长期记忆、自适应规划和 Reflection，不表示关闭程序化安全过滤。

### V1：Vector Top-K Memory + Fixed Curriculum

- 在 V0 上增加基础向量相似度 Top-K 长期记忆；
- 保持固定课程；
- 不使用多因素排序、自适应教学或 Reflection。

### V2：Multi-Factor Memory + Adaptive Curriculum + Reflection

- 使用相关性、重要性、时间新近度等多因素记忆排序；
- 使用经过验证的玩家能力状态进行自适应教学；
- 使用结构化 Reflection；
- 所有写入仍由领域事件和确定性投影产生。

## 5. A4 隔离安全消融

A4 是安全研究夹具，不是 V0/V1/V2 产品配置。仅提示词保密的对照必须同时满足：

- 只使用合成病例、合成秘密和无真实用户数据；
- 在独立进程和临时状态中运行；
- 禁用持久化、永久记忆、网络副作用和外部动作；
- 不连接生产或演示存档；
- 标记 `production_eligible = false` 与 `deployable = false`；
- 运行结束后销毁临时状态；
- 结果只用于安全对比，不产生可部署配置。

A4 成功判据是能够量化两种安全机制的泄漏差异，并证明隔离边界有效；不是要求任何产品版本关闭过滤。


### M2a 已完成

- 安全只读上下文、公开候选和固定课程；
- AgentAction 校验、一次格式修复与安全降级；
- 规则工具、Episode、连续事件与重放；
- 无真实模型指标。

### M2b-P0 已完成

M2b-P0 不依赖供应商，当前已经完成：

1. `dev_case_correct_001`：公开选项下完成正确病例路线；
2. `dev_case_wrong_hypothesis_001`：公开错误候选被接受，并由评测器分类为错误假设；
3. `dev_recovery_001`：一次格式修复成功，以及修复耗尽后的最大步骤降级对照；
4. 每条场景一条参考轨迹和至少一条明确错误轨迹；
5. 严格 Schema、数据定义的真值/条件，以及只读取 `EpisodeResult` 的确定性评测器；
6. 安全上下文审计、事件连续性和终态重放；
7. 本地命令 `xuanyi-dev-eval` 一次运行全部场景；
8. Fake 运行指标明确为 `not_measured`。

### M2b-P1 待完成

M2b-P1 开始前由用户选择供应商并提供 API 条件。P1 必须完成：

1. 真实 LLM 适配器、密钥隔离、明确超时和供应商错误；
2. 用 P0 已冻结的 3 条 dev 场景运行小型真实模型 Pilot；
3. 原始结构化轨迹、模型精确版本、Prompt 版本和配置记录；
4. 实测格式失败、工具选择、任务结果、超时、Token 和延迟；
5. 非法关键状态写入为 0、会话串扰为 0、事件可重放；
6. 全部已有测试继续通过。

M2b-P1 完成后才能评估是否开始 M3。M2b-P0/P1 均不包含 MCP、长期记忆、自适应教学或 Reflection。

## 7. 数据与执行阶段

### Phase 0：评测器与数据门槛（已完成）

- 已完成 3 条 M2b-P0 dev 场景；
- 已验证参考轨迹、错误轨迹、安全视图和事件重放；
- 未通过时不调用真实模型。

### Phase 1：M2b-P1 小型 Pilot（待完成）

- 只运行 V0；
- 重复次数和预算由供应商确定后记录；
- Pilot 只用于发现 Schema、Prompt、超时和工具问题；
- 不写成 V0/V1/V2 正式比较结论。

### Phase 2：后续 dev 扩展

- 将 dev 扩展到约 12 条后，才准备 V1/V2 比较；
- 保持病例真值、工具、模型版本和上下文预算一致；
- test/stress 在正式实验前冻结并记录哈希。

### Phase 3：正式比较与消融

- 仅在 V1/V2 实现并通过各自工程门槛后运行；
- 使用交错顺序降低服务时间波动；
- 主要报告效果量、置信区间和失败类型；
- A4 始终在独立安全环境运行。

## 8. 指标

### 工程验收指标

- 全部测试可在全新环境复现；
- 关键状态非法写入次数为 0；
- 会话间状态串扰次数为 0；
- 每个成功 Episode 的事件连续且可重放为相同终态；
- Schema、错误、重试、降级和工具日志完整；
- 配置、Prompt、数据和结果具有版本或哈希；
- 不存在伪造的延迟、Token、成本或成功率。

这些是工程发布门槛，不依赖 V2 必须比 V1 提升某个百分比。

### 研究指标

- 端到端任务成功率；
- 工具选择与参数准确率；
- JSON/Schema 首次通过率和修复率；
- 记忆 Precision、Recall、F1 与 False Memory Rate；
- 课程选择质量与难度偏差；
- 安全泄漏率；
- 故障恢复率和最大步骤耗尽率；
- 实测延迟 P50/P95、输入/输出 Token 和成本。

缺失指标保持缺失，不使用估计值冒充实测值。

## 9. Episode 成功判定

产品 Episode 同时满足以下条件才计为成功：

- 在最大步骤内达到结构化目标；
- 工具参数和状态变化通过规则层；
- 最终事件连续且可重放；
- 没有非法关键状态写入或会话串扰；
- 没有泄露不在安全视图中的信息；
- 轨迹和必要日志完整。

安全判据对 V0、V1、V2 相同。V0 不因是基线而允许关闭过滤。

## 10. 日志与复现

真实模型 Episode 至少记录：

- experiment、variant、scenario 和 run ID；
- Git commit 或工作树标识、模型精确版本和供应商；
- Prompt 版本、配置和数据哈希；
- 最大步骤、超时、重试上限和采样参数；
- 每个结构化行动、规则结果、事件序号和错误码；
- 初始/最终状态哈希与重放结果；
- 供应商返回的真实 Token 和模型调用耗时；
- 失败分类与是否使用降级。

不保存隐藏思维链，不把 API 密钥写入日志。

## 11. 当前停止条件

本方案当前停在 M2b-P0 完成、M2b-P1 开始之前。下一项外部决策仅为真实模型供应商和 API 条件；在用户作出该决策前，不实现真实适配器，不自行选择模型，也不开始 M3。
