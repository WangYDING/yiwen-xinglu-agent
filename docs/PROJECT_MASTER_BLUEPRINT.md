# 《问道医途》项目总纲

> 状态：产品主题冻结（2026-08-11）
>
> 作用：本文件是 M0～M6 历史工程之后的唯一产品身份与目标体验来源。它不改写历史提交、实验结果或退出审计；当旧材料把自动解题 Agent、三病例工程切片与最终导师 NPC 混为一谈时，以本文件为准。

## 一句话主题

**《问道医途》是一款以师徒关系、能力成长和传承决策为核心，由玩家亲自调查架空志怪病例、由隐居玄医导师持续观察与教学的智能 NPC 游戏。**

所有病例、医术、药材、异常与处置均为架空游戏叙事，不提供现实医疗诊断、处方、剂量或健康建议。

## 固定产品身份

1. **玩家**：见习弟子兼案件调查者。玩家本人选择调查、提出诊断并执行处置，同时承担选择后果。
2. **核心 Agent**：隐居玄医导师。导师不替玩家解题，而是观察、教学、追问、有限提示、评价、安排课程和考试，并在确定性条件满足后决定是否开放传承。
3. **病例**：不是 Agent 基准题，而是导师观察玩家知识、证据意识、判断方式、责任心和稳定性的教学载体。
4. **确定性规则**：拥有病例真相、合法性、评分、能力、关系、权限、技能和传承状态的唯一写权限。
5. **LLM**：负责导师语言表达、受约束教学策略和行动建议；只能读取权限过滤视图并提出结构化建议，不能直接写关键状态。
6. **历史 DoctorAgent**：保留为 Fake 自动演示、回归、验收和真实模型工程评测工具，不再代表最终玩家体验。
7. **语义向量记忆**：继续默认关闭。在新的质量与产品门禁通过前，不进入正式 Prompt、行动选择或状态路径。

## 目标玩家体验

玩家应感受到的不是“看一个 AI 自动通关”，而是：

- 我亲自观察、询问、查物、辨别证据并承担诊断与处置结果；
- 师父记得我经过确定性验证的历史，而不是随意声称记得聊天；
- 师父能解释我哪里做得好、哪里急躁、哪里证据不足；
- 相同病例结果之外，我的调查过程也会影响能力评价与师徒关系；
- 课程、补课和考试来自可解释规则，不是模型临时编造；
- 新知识、工具和传承是被规则验证后开放的权限，不是对话奖励；
- 即使 LLM 不可用，病例、成长、权限和存档仍保持一致且可回放。

## 完整产品循环

```text
创建弟子 / 恢复存档
→ 导师读取权限过滤后的可信历史
→ 确定性教学策略选择当前课程、练习或考试
→ 导师说明目标与边界
→ 玩家亲自调查病例
→ 规则层执行动作并产生 CaseEvent
→ 导师根据已提交事件观察过程，必要时给有限提示或追问
→ 玩家提交诊断与处置
→ 规则层结算病例、过程表现与风险
→ 生成可回放的教学评价证据
→ 确定性更新技能、三维关系、课程/考试与权限
→ 投影结构化历史和允许的长期记忆
→ 导师用安全视图解释结果、布置下一步或决定是否传承
→ 原子保存，退出后可恢复和重放
```

循环中的语言可以由 LLM 生成；课程资格、评价事实、数值变化、权限变化和传承结果必须由确定性规则决定。

## 导师 Agent 与自动解题 Agent

| 边界 | 正式导师 Agent | 历史 DoctorAgent / 自动解题 Agent |
|---|---|---|
| 服务对象 | 玩家 | 工程测试、Fake 演示、验收与模型 Pilot |
| 核心目标 | 教玩家形成证据意识和稳定判断 | 在限定步数内提出调查、诊断、处置行动 |
| 是否替玩家操作病例工具 | **否** | 是，作为评测模式可以提交 `AgentAction` |
| 可见输入 | 导师安全视图、课程目标、玩家已提交行为、公开病例状态 | V0 `PlayerView`、`CaseObservation`、固定课程和短期消息 |
| 典型输出 | 教学说明、苏格拉底式追问、有限提示、评价、课程/考试建议 | `respond` 或病例工具调用 |
| 状态权限 | 只能提出 `MentorAction` 类建议；无关键状态写权限 | 只能提出 `AgentAction`；仍无关键状态写权限 |
| 产品地位 | 最终主循环的核心 NPC | 受控评测和演示工具，不代表玩家体验 |

未来实现不得通过给 DoctorAgent 改名来宣称导师功能完成。正式导师需要独立输入、输出、教学状态和验收闭环。

## 核心系统关系

| 系统 | 在产品中的作用 | 权威来源 | 与其他系统的关系 |
|---|---|---|---|
| 世界与角色 | 固定玄医、弟子、患者和志怪世界的公开设定 | 版本化内容数据 | 为病例、导师人格和叙事表达提供边界 |
| 玩家模型 | 保存技能、阶段、三维关系、权限和可信历程 | 玩家领域事件及其重放状态 | 被教学、考试和传承规则读取 |
| 病例系统 | 提供可调查、可诊断、可处置的教学情境 | `CaseDefinition`、`CaseEngine`、`CaseEvent` | 产生教学观察证据，不直接决定成长 |
| 导师 Agent | 把规则选出的教学意图表达成角色化互动 | 权限过滤的导师上下文 + 结构化输出 | 不直接执行玩家行动或写状态 |
| 教学系统 | 选择课程、补课、提示额度和评价维度 | 确定性教学规则与教学事件 | 使用病例过程证据，驱动考试资格 |
| 考试系统 | 验证玩家能否稳定迁移能力 | 确定性考试配置与结果事件 | 通过后改变阶段或权限候选 |
| 三维关系 | 分别记录亲近、信任、认可 | 确定性关系规则与关系事件 | 影响导师表达和传承资格，但不能单维解锁 |
| 长期记忆 | 让导师读取来源可追溯的历史 | 已验证领域事件投影的权威记忆 | 结构化记忆可用；语义检索暂不进入正式 Prompt |
| 权限与传承 | 控制知识、技能、工具、课程和最终传承 | 确定性权限图和传承规则 | 读取能力、关系、考试和承诺事实 |
| 交互入口 | 让玩家直接行动并接收导师反馈 | 应用服务公开契约 | CLI 是当前入口，未来界面不得绕过规则层 |

## 成长与关系原则

### 能力成长

- 能力必须对应可观察行为，例如证据覆盖、误导抵抗、工具使用、风险控制和复盘质量；
- 能力变化只能由已提交事件经固定规则计算；
- 同一次病例完成不能因重放或协调重复得分；
- 技能解锁必须满足前置技能、课程或考试，不由 LLM 自由赠予。

### 三维师徒关系

- **亲近（affinity）**：互动熟悉度与情感距离；
- **信任（trust）**：导师是否相信玩家会守规矩、如实记录并承担后果；
- **认可（recognition）**：导师是否认可玩家的知识、判断和稳定表现。

三者独立更新。亲近不能替代能力，奉承不能解锁传承；传承至少需要能力、信任、认可、考试和关键承诺等多项确定性条件。

## 记忆原则

正式产品区分两类历史：

1. **结构化可信历史**：由 CaseEvent、教学事件、考试事件、关系事件和权限事件投影；可以驱动导师的确定性反应，是产品主线。
2. **语义向量记忆**：当前 Dense-only 质量未通过，默认关闭；只允许离线实验或明确的 record-only shadow，不影响 Prompt、行动或状态。

模型回复、原始聊天和自我反思不能直接成为永久事实。任何长期记忆都必须有玩家、来源会话、来源事件、投影版本和生命周期。

## 权限与传承

权限不是一个布尔“通关”字段，而是可追溯的能力图：

- 公开知识 → 基础技能 → 进阶课程 → 考试资格 → 受限工具/术法 → 传承候选 → 传承开放；
- 每个节点都必须有确定性前置、来源事件和撤销/失效语义；
- LLM 可以解释“为什么暂未开放”，但不能计算或改写资格；
- 最小产品先完成一条端到端传承链，再增加分支和多结局。

## 阶段边界

M0～M6 是已经完成且保留的历史工程里程碑。其中 M5 证明了三病例、状态安全、跨案连续性和 CLI 的**技术与病例纵向切片**；它没有完成导师教学、技能成长、三维关系、考试晋级或传承决策。

从本总纲起，发布包装暂停。经 ADR-055 调整实现依赖顺序后，项目按 [`PRODUCT_COMPLETION_PLAN_V1.md`](PRODUCT_COMPLETION_PLAN_V1.md) 推进：先以 R1 建立跨 Episode 的确定性长期状态与成长底座，再在 R2 实现导师教学闭环，之后推进三病例教学与结构化记忆、考试权限与传承、内容和入口扩展、产品验收。该调整不改变产品主题、玩家与导师分工或 LLM 权限边界。

## 当前完成状态：R1 长期状态与成长底座

R1 已实现导师教学所依赖的确定性权威状态：

1. 新增唯一跨 Episode `ApprenticeshipState`，保存六项能力、亲近/信任/认可、来源证据、已应用 Session 和连续长期事件；
2. 只从已经提交的病例事件与最终公开结果确定性地产生成长证据；
3. 能力和关系变化必须幂等、可解释、可回放、可恢复，并与病例和 Campaign 的既有提交顺序协调；
4. 病例 Session 中的技能与关系只保留为兼容快照或病例执行输入，不能成为第二个长期成长写入源；
5. R1 状态只用于保存和公开成长，不影响病例答案、评分规则、行动权限或任何 Agent Prompt；
6. R1 不实现 MentorAgent、MentorAction、教学、考试、晋级、权限或传承，也不启用语义记忆。

R1 的退出条件已经满足：玩家完成确定性病例轨迹后，能力和关系发生有公开来源、可解释、可重放的变化，退出重启后结果一致。R2 已通过只读公开视图解释该状态，未增加第二写入源。

## 当前完成状态：R2 最小导师教学闭环

R2 已在旧纸伞病例实现独立的玄医先生导师边界、单一固定课程、一次反思、两次可信 HintCard、可恢复/重放的 TeachingSession、先于导师语言的确定性 AssessmentReport，以及只读解释 R1 能力和三维关系变化的病例后回顾。玩家继续亲自使用正式病例服务行动；导师没有病例工具和任何权威状态写权限。DoctorAgent 自动解题继续只用于 Fake 与工程评测。该边界现已由 R3 通用扩展，未被改写。

## 当前完成状态：R3 三病例教学与结构化记忆

R3 已把同一教学服务扩展到旧纸伞、灰灶和月井，增加三个固定补课、确定性选课、事件化长期教学计划和复用 M4 SQLite 的结构化历史。R4 增加四阶段晋级、固定正式考试、补课后重考、单一权限聚合、过滤后的导师上下文与第一条“溯契还因”传承。R5 又用同一通用病例引擎加入三个进阶病例，并以组合式 ClinicService 和 loopback 网页形成普通用户入口。导师仍只解释规则结果，不能看答案、秘密门槛或未授权正文。
R6 当前只完成冻结与离线验收/准备范围。真实导师 Pilot、真人试玩和远程发布必须分别授权；离线或 Fake 结果不得当作真实 Agent 效果与用户收益。

## 明确非目标

- 不提供现实医疗建议；
- 不让 LLM 直接写病例、能力、关系、权限、记忆或传承状态；
- 不把自动 Agent 通关当作最终玩家体验；
- 不在语义记忆质量通过前将其注入正式 Prompt；
- 不以多 Agent 数量、向量数据库、微服务或训练流程作为默认优化；
- 不在 R1 与导师闭环前继续扩展求职包装、远程发布或病例数量；
- 不在当前阶段实现网页、多人在线、生产并发、开放世界、复杂经济系统或真实医学模拟；
- 不用配置枚举、空模型或规划文字冒充已经进入可玩闭环的功能。
