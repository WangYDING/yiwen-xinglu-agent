# M5 产品差距审计

> 审计日期：2026-08-11
>
> 审计对象：M5 结束后的实际产品能力
>
> 结论边界：M5 是技术与病例纵向切片，不是《问道医途》导师 NPC 产品目标的完成证明。

## 统一成熟度

- **L0 未实现**：没有可执行契约或产品能力。
- **L1 概念或数据结构**：只有设计、配置、Schema、枚举或静态数据。
- **L2 确定性规则**：存在可执行规则、状态边界和自动测试，但未进入完整玩家闭环。
- **L3 已进入可玩闭环**：普通玩家可操作、保存和恢复。
- **L4 真实模型或完整工程验证**：在 L3 之外具有真实模型或跨进程、完整工程门禁证据。
- **L5 真实玩家验证**：具有真实目标用户试玩、观察和结果证据。

成熟度按该产品能力最弱的关键链路判定。专项基础设施达到更高等级时会在证据中注明，但不能抬高尚未进入产品的能力。

## 逐项审计

| 模块 | 当前证据 | 成熟度 | 主要缺口 | 下一验收条件 |
|---|---|---:|---|---|
| 病例状态机与回放 | 三个病例复用 `CaseEngine`；事件连续、结局/评分确定；JSON 持久化、跨进程恢复和终态重放已验证 | L4 | 尚无生产并发和真人玩法证据 | 在导师教学闭环中继续保持拒绝零写入、退出恢复和事件重放一致 |
| Agent 工具和安全恢复 | 严格 `AgentAction`、公开行动契约、9 个 MCP 工具、一次格式/契约修复；P4b 负结果与 P4d 5/5 单次恢复案例均保留 | L4 | 当前 Agent 主要替玩家解题；真实行为只是一正一负的单次案例，无稳定成功率 | 把工具型自动解题明确留在评测模式；正式导师输出不得代替玩家操作 |
| 三病例玩法 | 旧纸伞、灰灶、月井均有调查、诊断、三类处置、多顺序和无 Key CLI | L3 | 内容量仅三案；导师没有把病例组织成课程体验 | 一个病例先接入导师案前目标、过程观察、提示和案后反馈，再扩内容 |
| Campaign 连续性 | 三案完成摘要、两项公开知识和两处历史反应由 `CampaignEvent` 幂等投影；推荐顺序不锁关 | L3 | 主要是预写跨案反应，不等于导师理解成长或关系 | 导师安全视图读取结构化 CampaignFact，并由规则选择对应反应 |
| 导师人格 | V0 Prompt 使用“道医师父”语气，文档有角色定位 | L1 | 运行中的 DoctorAgent 仍以自动解题为目标；没有独立导师输入、教学动作和持续人格验收 | 玩家手动完成一案，导师完成案前说明、一次有界提示、案后角色化反馈，且不调用病例工具 |
| 玩家技能成长 | `SkillState`、初始技能和病例技能门禁存在 | L1 | 没有从表现证据到技能变化的规则、事件、幂等结算和可见反馈 | 冻结一个能力维度，依据已提交过程事件确定性更新并可重放，重复结算不重复得分 |
| 亲近/信任/认可关系 | `RelationshipState` 有三维字段和范围校验 | L1 | 没有三维独立更新规则、关系事件、公开解释或传承读取 | 为三类可验证行为各定义映射；至少一个正向和一个负向路径进入可玩闭环 |
| 自适应教学 | 旧规划和变体配置提及 V2 | L0 | 没有课程选择器、补课规则、能力诊断或可玩闭环；配置名不算实现 | 在固定教学闭环和成长证据稳定后，按公开能力缺口选择两个课程之一并可解释 |
| 考试晋级 | `TeachingStage` 有 NOVICE/ADVANCED/EXAM 枚举 | L1 | 无考试定义、资格、会话、通过/补考、阶段事件 | 完成一项课程资格→考试→确定性结算→阶段更新的可重放路径 |
| 长期记忆工程与产品作用 | M4 的 SQLite 来源链、生命周期、玩家隔离和 Fake Top-K 工程闭环；M4.5 本地 BGE 双运行诚实失败；M5 正式连续性使用结构化 CampaignFact | L2 | 记忆基础设施工程证据较强，但语义检索默认关闭，导师尚未消费结构化历史；不能声称产品记忆体验完成 | 仅将允许列表结构化历史加入导师安全视图，证明导师反应变化且规则、行动和状态不受模型改写 |
| 知识权限与传承 | Campaign 解锁两项公开知识；技能前置数据存在 | L1 | Campaign 知识不是完整权限图；无撤销、考试前置、传承资格或最终决策 | 实现一条知识→课程→考试→关系/承诺门槛→传承开放的确定性事件链 |
| 普通玩家入口 | `xuanyi-play` 支持创建/选择玩家、三案、退出恢复；wheel 安装后可无 Key 运行 | L3 | 仍是终端界面，导师教学流程未出现；未做可用性测试 | 新手不编辑 JSON 或内部 ID 即完成导师教学闭环；记录真实操作问题 |
| 内容规模 | 3 个完整架空病例，每案可独立完成并有三类结局 | L3 | 尚不足以承载课程、补课、考试和长期成长；主题复用风险未验证 | 先形成教学模板，再扩到 6 案，逐步达到 10–15 案；新增内容都需双路径、回放和安全审计 |
| 真人试玩 | 有自动验收、CLI 演示脚本和录屏方案 | L0 | 无真实玩家任务完成、理解度、误操作、体验或留存证据 | 预注册小型试玩任务、隐私同意和观察指标，至少完成首轮真实用户测试并保留脱敏证据 |

测试总量不是本表的成熟度依据。测试用于证明边界和回归；“玩家是否真的经历导师教学与成长”必须由可玩闭环和后续真人证据回答。

## 当前最关键的五个产品缺口

1. **导师角色尚未成为产品主循环**：现有真实模型路径仍是自动解题 Agent，玩家与导师之间没有独立教学协议。
2. **过程表现没有形成能力成长**：病例能结算，但证据意识、工具使用、误导抵抗等表现没有确定性沉淀为技能变化。
3. **三维师徒关系只有字段**：亲近、信任、认可没有来源事件、独立规则和可见后果。
4. **课程—补课—考试—晋级链为空**：现有阶段枚举不能安排教学，也不能验证学习迁移。
5. **权限与传承没有端到端链路**：两项 Campaign 知识不等于技能授权或传承；导师也尚未用结构化可信历史解释传承决定。

内容规模、图形界面和真人试玩同样重要，但应在上述核心循环至少完成一条后推进，否则只会扩大缺少导师体验的内容量。

## M5 后续顺序修订：先实施 R1 成长底座

本节保留 M5 的历史审计结论，但后续实现顺序已由 ADR-055 和 [`PRODUCT_COMPLETION_PLAN_V1.md`](../product/PRODUCT_COMPLETION_PLAN_V1.md) 修订。M5 仍未实现成长或导师教学；不得把本次顺序调整回写成 M5 能力。

R1 已在 M5 历史关闭之后完成以下验收；这不改变上表对 M5 当时能力的审计：

1. 已提交病例事件和最终公开结果投影为来源可追溯的六项能力证据；
2. 唯一跨 Episode `ApprenticeshipState` 确定性更新能力和三维关系；
3. 成长事件连续、可回放、跨玩家隔离，重复完成或协调保持幂等；
4. 病例、Campaign 与成长投影的失败窗口可显式恢复；
5. 完成结果和 CLI 只公开必要成长变化，不泄露病例真相或内部门槛；
6. R1 不实现导师 Agent，且长期状态不影响病例答案、评分、行动权限或 Agent Prompt。

R2 尚未开始；届时才实现原计划中的玩家手动行动、案前目标、有限提示、结构化师评和导师表达，并只读 R1 状态；导师仍不能直接修改能力或关系。

## 现有展示文案偏差记录

本轮按要求不修改 README 或 M6-P2 素材，只记录需要总纲冻结后统一纠正的位置：

- `README.md:1` 的“师承型智能 NPC”标题容易让人误以为导师教学闭环已经完成。
- `README.md` 首屏把 CLI、Fake/DeepSeek 与 MCP 放在同一“行动入口”叙事中，没有首先区分“玩家行动”和“自动解题评测”。
- `README.md` 的“可玩产品”表述对三病例切片成立，但与项目名连读时可能被理解为完整导师 NPC 已可玩。
- `docs/M5_PORTFOLIO_EVIDENCE.md` 的“真实 Agent 体验”重点是 P4d 自动完成病例，应明确它属于工程评测，不是最终玩家体验。
- `docs/M5_EXIT_AUDIT.md` 已写明 Fake 是回归/演示而非玩家决策模型，但首页短路径没有同等醒目的限定。

这些是表述层偏差，不改写 M5、M6-P2 的历史验收和素材来源。后续统一修正必须以 [`PROJECT_MASTER_BLUEPRINT.md`](../architecture/PROJECT_MASTER_BLUEPRINT.md) 为准。
