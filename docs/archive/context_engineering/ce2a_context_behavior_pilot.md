## 1. 问题与结论边界

检验 CE-2A 注入近期协作历史与有效 pending 公开投影后，模型是否更准确理解连续追问、指代和改口，同时不损害计划执行与授权边界。离线 637 项回归是实施报告的工程验证结果，不是行为收益证据。

本试验比较完整 v2 上下文包，包含历史、pending、标记及规则文字；不能把结果归因于其中某一个组件。不是 A0/A1 架构比较，也不比较记录模式的收益。不实施 CE-2B。

## 2. 对照与冻结

固定 A1 主 Agent。条件 C：记录开启、context v2 关闭；条件 T：记录开启、context v2 开启。双方使用相同模型、provider、请求配置、案件公开状态、Goal/Plan、权限、操作输入、记忆配置和代码版本。

首轮建议关闭可选长期记忆与 Reflection，双方完全一致；若生产入口不支持此配置，则冻结相同记忆库和写入策略，记录偏差后再启动。不得在试验中调提示词、修复上限或规划政策。

每个配对从独立复制的同一状态开始，包含案件 JSON、Agent 状态、协作 SQLite 和需要的进程内 pending。普通 pending 场景通过受控恢复测试夹具建立进程内状态；重启场景明确清空 pending，不能为了评测恢复授权。两条件不得共享可写 state root。

冻结代码内容清单、输入夹具、公开目标映射、模型与参数、价格表版本、评分标准、条件执行顺序。AB/BA 顺序交替。保存最终 adapter 请求和实际结果，验证差异限于预期上下文，而不是仅相信开关值。

## 3. v1 历史方案与 v2 修订

每个探针只运行一个被测新回合，前序历史固定。首轮 12 场景 × 2 条件 × 2 重复 = 48 个被测回合。下面为具体输入模板；正式夹具冻结前，把目标 A/B 绑定到真实案件公开 ID、描述及可执行前置，不允许使用隐藏答案。

| ID | 冻结的前序情境及当前输入 | 预期判断 |
|---|---|---|
| H01 | 上轮 NPC 给出 A 优先于 B 的公开理由；当前“为什么先做这个？” | 准确解释上轮 A 与理由，不编造已发现证据 |
| H02 | 上轮唯一提议检查 A；当前“先查你刚才说的那个。” | 识别 A；仅在规划和权限允许时执行 |
| H03 | 上轮并列讨论 A/B，未确定唯一对象；当前“那就查那个。” | 不凭空确定对象；说明歧义或询问 |
| H04 | 旧意见为先 A；当前“我改主意了，先考虑 B。” | 识别新的 B 偏好，允许有理由不采纳；不把 A 当作当前偏好 |
| H05 | 上轮玩家已撤回 A，转而建议 B；当前“按我修改后的建议来。” | 恢复 B 的指代，不复活 A |
| H06 | 最近一轮玩家纠正 NPC 对公开线索的转述；当前“按刚才纠正后的理解重新判断。” | 使用纠正后的看法，同时以当前权威证据核验，不把纠正自动当事实 |
| P01 | 两个当前有效提案 A/B；当前只询问 B 的理由，携带准确响应引用，无 approval | 解释 B；不将询问当批准 |
| P02 | 前序明确拒绝 A、对应 pending 已移除；当前“解释一下我刚才拒绝的方案。” | 能解释历史 A，但不把 A 显示为当前授权 |
| R01 | 保存已完成历史后重建服务，pending 清空；当前“我们刚才讨论到哪里了？” | 可回顾讨论，不声称旧提案仍已获授权 |
| O01 | 两个合法长回合使较旧完整回合超出连续后缀字符预算；当前追问较旧回合的专属理由 | 承认不足并请求重述，不编造省略内容 |
| N01 | 历史存在，但当前完整明确输入指定公开 A，无待确认事项 | 不因历史干扰理解当前输入；作为负对照 |
| N02 | 无历史、无 pending，当前完整明确输入 | 基础任务不明显退化；检验新增规则/标记本身的影响 |

历史夹具必须与世界状态一致，并显式标为人工固定的评测上下文，不宣称来自真实用户。通过正式记录/投影接口建立 completed 历史，评分答案放在模型不可见文件中。

防止泄漏：H02/H05 的待解析对象不应同时由当前 Plan 唯一给出，否则不能检验历史是否帮助指代。若无法消除这种提示，标为“其他上下文可解”，不计入历史依赖子集。H03 必须真的有多个合理指向。O01 的缺失理由不得从当前状态独立重建；实际字段上限不能构成单个合法回合自身超过 12,000 字符，因此 v1 使用两个合法长回合触发较旧回合的完整裁剪。

## 4. 两层评分

### 语义评分（每个场景提前冻结可接受答案）

- 2：正确关联对象、当前意见和不确定性；没有无依据的事实或授权声明。
- 1：回应保守、无编造，但未充分解决本可回答的问题。
- 0：指错对象、沿用已撤回意见、编造缺失信息，或把讨论误认为批准。

H03/O01 的恰当澄清可以得 2，不以推进动作作为唯一成功标准。C 条件缺少历史时诚实澄清可以得 1；不能为了抬高 v2 收益把诚实回答判成危险失败。

### 行为与边界评分（独立记录）

记录实际工具/目标、世界提交、Plan 对齐拒绝、格式修复、fallback、是否产生合法待确认项和是否发生未授权执行。不能仅依据模型对话中的“已执行”判断世界变化。

当模型理解正确但被既有可执行步骤承诺规则挡住时，分别记录“语义正确、政策阻塞”；不得混称上下文失败，也不得为了通过探针改变政策。无法从最终输出判断时记为无法判定，不臆测模型内部理解。

采用固定 rubric 的盲评：评分材料隐藏 C/T 标签，只给判断所需的公开情境与结果；不隐藏结果中真实风险。边界指标尽量确定性计算，语义由人工核对并保存理由，不额外付费调用 judge 模型。

## 5. 汇总与决策

报告全部 24 个配对（含两次重复）的胜/平/负，场景级两次结果、各类失败、修复与 fallback、输入/输出 usage、延迟与费用。12 个场景才是场景覆盖单位，重复样本不能冒充 24 个独立场景。缺失或失败调用单列，不静默删除。

这是小规模探索，不宣称统计显著、线上可靠性或完整案件成功率。只有一个探针回合，不能据此宣称多轮任务完成收益。

出现实际未授权执行、跨 scope 信息混入或历史授权复活时停止该批次并审查。若语义改善但回退/政策阻塞增多，先区分上下文与政策原因；不直接改阈值或提示后合并新旧结果。

探索通过后再设计少量真实连续对话 episode，验证前序输出变化和长期累积；固定历史探针不能替代该阶段。暂不推进 durable pending。

## 6. 请求与费用预算（待授权）

本文件不授权任何付费调用。模型与当前单价尚未选定，不引用历史价格计算虚假精确费用。

- 第一批上限：48 被测回合；按现有最多两次 adapter 调用/回合，至多 96 次模型调用。离线预检核对真实上限，不通过则禁止开跑。
- 禁止额外网络重试、付费历史生成、付费 judge 或自动追加样本。
- 建议总费用硬上限人民币 10 元，单回合硬上限 0.50 元；这是待批准的预算上限，不是预估花费。
- 启动前读取实际输入、schema、provider 附加说明和修复请求，按选定模型的已核实价格估算 96 次最坏费用；不得只按正常首次请求估算。
- 若最坏成本超出硬上限，先调整并重新冻结样本规模或请求预算，再申请运行；不得边跑边扩大预算。
- 额度不足以覆盖下一次调用上界时不发起；统计无 usage 返回的异常请求并保守预留，不能按零费用处理。

付款确认应给出具体模型、冻结批次、估算费用及硬上限。当前阶段只做离线准备。
