## P0/P1 分层证据

### M3-P0：工具契约与进程内边界

1. 项目依赖声明使用官方 `mcp==2.0.0`；专项测试同时检查运行环境中的准确版本。
2. `FROZEN_MCP_TOOL_NAMES` 固定 9 个工具，官方进程内 `Client(server)` 发现结果与名称、数量和顺序完全一致；各输入 Schema 均为 `additionalProperties=false`。
3. MCP handler 只校验参数并调用 `MCPApplicationService`。应用 Facade 复用 `JsonStateStore`、`AgentContextFilter`、`V0ToolExecutor`、`FixedV0DiagnosisReadinessPolicy` 和 `CaseEngine`，不直接修改 `CaseSessionState`，不自行生成事件或复制病例规则。
4. 参数错误、领域规则拒绝和未知内部错误统一返回严格结构化、安全脱敏的结果；规则拒绝同时返回刷新后的 `PlayerView` 和 `CaseObservation`。
5. `diagnosis_not_ready`、未知调查、重复调查、未知字段、错误类型、策略绕过和持久化失败均验证为空事件、不增加修订、不保存新状态；会话文件逐字节保持一致。
6. 进程内 MCP 完整参考轨迹产生连续事件 1–8，最终状态与直接调用同一应用服务完全一致，为 `completed / resolved / 100`。

### M3-P1：真实 stdio 子进程边界

1. `xuanyi-mcp-stdio` 和模块入口只接受显式病例目录、状态目录；进入 stdio 传输前验证目录和全部病例 JSON。
2. 集成测试使用官方 `StdioServerParameters`、`stdio_client` 和 `Client` 启动真实独立 Python 子进程，不使用 P0 的进程内捷径。
3. 第一进程发现准确的 9 个工具，完成只读调用、一次提前诊断拒绝和事件 1 后以退出码 0 结束；第二进程使用不同 PID，从同一临时磁盘状态恢复修订 1，完成事件 2–8 后以退出码 0 结束。
4. 两个客户端上下文关闭后服务器进程均已退出，没有孤儿进程；跨进程最终状态为 `completed / resolved / 100`。
5. 正常运行期间 stderr 为空，官方客户端成功解析全部 stdout 协议帧。模块导入不输出、不写状态；缺少参数、目录无效和病例损坏均在服务启动前非零退出，stdout 为空、无 traceback、文件不变。
6. 所有 P1 测试使用临时病例和状态目录，没有访问或修改仓库中的真实玩家、历史会话和结果文件。
