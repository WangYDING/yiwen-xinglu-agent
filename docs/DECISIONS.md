# 架构决策记录

本文件记录会影响实现边界或后续返工成本的决策。新决策追加记录，不静默改写历史结论。

## ADR-001：确定性领域层拥有关键状态

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：病例真相、能力值、关系值、权限、动作合法性、技能解锁和最终状态修改只能由确定性领域层负责。Agent 只能输出经过校验的语言、工具请求或状态变化建议。
- **原因**：避免模型幻觉直接污染游戏状态，使行为可测试、可审计和可回放。

## ADR-002：M0 使用 Pydantic v2 和 `src` 布局

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：领域对象使用 Pydantic v2；项目采用 `src/xuanyi_npc` 包布局，测试使用 pytest。
- **原因**：Pydantic 同时提供运行时校验、JSON 序列化和后续结构化输出 Schema，`src` 布局可避免测试误用仓库根目录中的未安装模块。

## ADR-003：M0 使用原子 JSON 文件验证持久化接口

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：M0 仅为玩家状态和病例会话提供原子 JSON 保存/读取接口，运行数据写入被 Git 忽略的 `runtime_data`；SQLite 延后到需要事件查询和记忆检索时引入。
- **原因**：先验证模型边界和存储接口，避免在领域模型尚未稳定时绑定数据库表结构。

## ADR-004：首个病例是可替换的技术夹具

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：“旧纸伞与失约书生”仅用于验证线索、调查、误导、诊断、处置和评分结构，不作为最终世界观承诺。患者和灵体在垂直切片阶段不是独立 Agent。
- **原因**：优先完成一个可测试闭环，减少世界观未决事项对工程进度的阻塞。

## ADR-005：MCP 不包含业务规则

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：后续 MCP 工具只调用应用服务；动作校验和状态更新继续由领域层实现，不在 MCP Server 中复制规则。
- **原因**：保证命令行、测试、未来界面和 MCP 共用同一套确定性行为。

## ADR-006：M1 使用命令—事件—新状态执行模型

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：`CaseEngine.execute()` 接收病例、玩家、当前会话和一个带时区时间戳的结构化命令，返回新会话、领域事件及用户可见结果。引擎不原地修改输入；失败通过具体 `RuleViolation` 子类型返回，且不产生部分状态。
- **原因**：保证同样输入得到相同结果，并为后续日志、MCP 工具、回放和故障分析提供稳定边界。

## ADR-007：M1 的病例评分保持确定且可解释

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：当前总分由已发现关键线索占比、诊断正确分、根因处置分和危险处置惩罚构成，并限制在病例配置的最高分内。提示扣分、心性评价、技能成长和关系变化推迟到教学阶段。
- **原因**：先验证病例过程与结果的评分闭环，避免在教学和关系规则确定前混合多个尚未实现的维度。

## ADR-008：Agent 上下文采用检索前最小权限视图

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：模型只能接收 `PlayerView` 与 `CaseObservation`。视图构建时只加入当前已经解锁或发现的内容，并移除病例根因、因果链、未发现线索、隐藏信息、合法诊断集合、处置结果、评分规则、技能前置条件及关系原始值。
- **原因**：秘密不能在进入 Prompt 后再依赖提示词保护；未授权内容必须在模型调用前从数据层移除。

## ADR-009：V0、V1、V2 共用 EpisodeResult 并采用递增能力边界

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：V0 使用短期上下文、固定课程、结构化行动和基础工具；V1 只在 V0 上增加经过验证的跨回合记忆；V2 再增加自适应教学和 Reflection。三个版本共用 `EpisodeResult`，确保后续对比实验的输出结构一致。
- **原因**：避免版本间同时改变多个变量，使记忆和教学能力的增益能够通过真实消融实验复核。

## ADR-010：模型不能直接提交永久记忆或关键状态

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：从 Agent 工具集合移除永久 `record_memory`，并从 `AgentAction` 移除关系、技能状态变化提议。未来永久记忆必须由已验证领域事件经过记忆投影策略生成；模型文本最多作为待验证候选内容。
- **原因**：防止提示注入、幻觉或工具误用直接污染长期状态，并保留记忆来源以供审计。

## ADR-011：事件重放是状态一致性的发布门槛

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：病例引擎产生的事件必须能够从同一初始 `CaseSessionState` 重建完全相同的最终状态；事件序号断裂、会话不匹配、结束后事件和无证据诊断事件必须拒绝重放。
- **原因**：保证日志不仅可查看，还能用于故障恢复、评测复核和状态一致性验证。

## ADR-012：公开历史不保留本地占位邮箱

- **状态**：已接受，推送前待执行
- **日期**：2026-08-03
- **决策**：当前本地提交使用 `wyd@localhost`，但首次公开推送前不保留该地址。取得用户确认的 Git 邮箱或 GitHub noreply 地址后，统一改写本地提交作者；提交哈希变化后同步更新所有记录和交付材料。未取得确认前禁止公开推送，不猜测用户邮箱。
- **原因**：避免作品集公开历史包含不可关联的占位身份，同时避免助手擅自写入错误个人信息。

## ADR-013：安全过滤不是产品消融变量

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：V0、V1、V2 全部强制启用 `AgentContextFilter`。“提示词保密 vs. 程序化过滤”仅作为离线 A4 安全消融，使用合成数据、禁用持久化和外部动作，并明确标记不可部署。
- **原因**：消融实验不能制造容易误部署或污染真实状态的不安全产品版本。

## ADR-014：V1 与 V2 使用不同复杂度的记忆检索

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：V1 仅增加基础向量相似度 Top-K 长期记忆检索并保持固定课程；V2 才使用相关性、重要性、时间新近度等多因素记忆排序，同时加入自适应教学和 Reflection。
- **原因**：确保 V0→V1 主要测量基础长期记忆价值，V1→V2 再测量排序、教学适配和 Reflection 的联合增益。

## ADR-015：M2-V0 使用只读 Agent 提议与有界失败策略

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：V0 的 `DoctorAgent` 通过可替换 `LLMAdapter` 接收权限过滤后的 `PlayerView`、`CaseObservation`、最近有限条消息和只按步骤编号推进的固定课程。模型输出必须校验为 `AgentAction`，并使用应用层指定的本步 `action_id`；首次格式失败只允许一次修复请求，第二次失败或供应商调用失败时返回不含工具调用的确定性 `respond` 降级动作。模型不接收 `CaseDefinition`、可写会话或应用层时间戳。
- **原因**：建立可复现实验基线，同时限制格式错误、供应商异常和模型越权对状态机的影响。

## ADR-016：V0 工具层只翻译命令，不复制病例规则

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：V0 工具执行器使用严格参数模型，将 Agent 工具建议翻译成既有领域命令。调查目标和命令时间由应用层补齐；技能、线索、证据、处置前置条件及会话状态继续由 `CaseEngine` 校验。成功状态变化只来自引擎事件；拒绝只记录错误码，并向下一次模型调用提供不包含隐藏门槛细节的统一反馈。M2 不实现 MCP、长期记忆、自适应课程或 Reflection。
- **原因**：保证测试、未来界面和 MCP 共用同一规则来源，并防止模型通过伪造参数或错误消息侧信道改变、探测关键状态。

## ADR-017：M2 拆分为 M2a Harness 与 M2b 真实模型验证

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：当前 Fake LLM、结构化行动、只读上下文、规则工具和 Episode 闭环统一记为“M2a：Fake LLM Agent Harness 与安全闭环完成”。“M2b：真实 LLM 适配、3 条 dev 场景、小型 Pilot、真实超时/Token/延迟验证”尚未完成。在 M2b 验收前，不得把整个 M2 标记为完成，也不得开始 M3。
- **原因**：Fake 脚本能证明编排和安全边界可运行，但不能证明真实模型能理解公开语义、稳定选择工具或满足供应商运行约束。

## ADR-018：Agent 使用公开诊断词表，正确性仍由领域层持有

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：每个病例必须提供至少两个公开诊断候选，包含候选 ID 和中立公开说明，并同时包含至少一个有效候选和一个合理错误候选。内部 `root_cause` 与公开候选 ID 分离；`valid_diagnosis_ids`、候选正确性、评分和隐藏门槛不进入 Agent 视图。规则层接受词表内的错误候选并按既有规则计分，使用 `unknown_diagnosis` 拒绝词表外 ID，失败不产生状态变化。调查和处置也提供独立公开说明，但不复用会泄露结果或门槛的内部说明。
- **原因**：真实模型必须从安全上下文获得可提交标识，同时不能因接口可用性而泄露 Gold 答案或确定性世界真相。

## ADR-019：ROADMAP 与实验方案 v0.2 成为当前规划来源

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：仓库内 `docs/ROADMAP.md` 是唯一有效的里程碑状态来源；README、最新 ADR 和验证记录与其同步。Word 设计总结、`xuanyi-npc-handoff` 和实验方案 v0.1 保留为历史基线，不再表示当前执行状态。实验方案 v0.2 规定所有产品版本强制使用 `AgentContextFilter`，仅提示词保密只允许作为不可部署的隔离 A4 消融。
- **原因**：消除历史规划、实现状态与安全实验定义之间的冲突，避免把研究目标误写成工程完成条件。

## ADR-020：M2b 拆分为供应商无关 P0 与真实模型 P1

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：M2b-P0 先以严格数据 Schema 定义 3 条 dev 场景，为每条场景保存一条参考轨迹和至少一条明确错误轨迹，并由只接收统一 `EpisodeResult` 的确定性评测器分类。场景真值、成功条件和失败条件只存在于评测数据，不进入 Agent Prompt；Fake LLM 运行不填写延迟、Token、成本或真实成功率。M2b-P1 才实现用户选定供应商的真实 `LLMAdapter`，使用 P0 场景运行小型 Pilot 并采集真实指标。P1 完成前整个 M2 保持进行中，M3 禁止开始。
- **原因**：dev 数据与评测逻辑不依赖供应商选择，可以先冻结并测试；把真实适配和指标留到 P1，能够避免 Fake 结果冒充模型能力，也使后续不同供应商共用同一确定性门槛。

## ADR-021：真实数据产生前将 ModelUsage 改为供应商无关契约

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：删除只适用于美元的 `cost_usd`，统一记录输入、输出、缓存命中输入、缓存未命中输入、推理 Token、真实延迟、估算成本、ISO 币种、供应商返回模型、可选请求 ID 与系统指纹。估算成本和币种必须同时存在或同时缺省；Episode 只聚合同币种的完整成本。发生已收费但用量不完整的失败时保留已知用量并标记 `measurement_complete = false`，后续预算门禁停止新 Episode。Fake LLM 继续不创建 `ModelUsage`。
- **原因**：DeepSeek 按人民币及缓存分项计费，强制换算美元会引入不可复现的临时汇率；在首个真实 Pilot 前调整 Schema，不会迁移或污染任何真实实验记录。

## ADR-022：M2b-P1a 使用 DeepSeek 直接 HTTP Adapter 并隔离付费执行

- **状态**：已接受
- **日期**：2026-08-04
- **决策**：首轮供应商固定为 DeepSeek 官方 API，模型只允许 `deepseek-v4-flash`。Adapter 继续实现既有 `LLMAdapter`，通过 `httpx` 调用标准 `/chat/completions`，不使用供应商原生工具调用、Beta strict tools 或隐式重试；请求固定使用 JSON Output、非流式、温度 0 并关闭思考。P1a 只完成 MockTransport 离线验证、只读模型发现和预算门禁。真实 `/models` 与付费 Chat 请求属于 P1b，必须由用户再次授权，且 Pilot 命令还要求显式 `--confirm-paid-pilot`。
- **原因**：保持模型只提出 `AgentAction`、应用层执行工具的安全架构，同时把协议实现与会产生费用的实验执行拆开，避免预检阶段误用 Key 或产生费用。

## ADR-023：允许从项目根目录加载本地 `.env`

- **状态**：已接受
- **日期**：2026-08-06
- **决策**：DeepSeek 配置在未传入显式配置映射时，读取当前项目目录的 `.env`，并以操作系统环境变量覆盖其中的同名值。解析过程不修改进程环境，只读取允许的 DeepSeek 与 Pilot 配置项；真实 `.env` 继续由 Git 忽略，`.env.example` 只保存占位符。
- **原因**：将开发密钥限制在项目级配置中，降低全局环境污染，同时保留 CI、临时会话和部署环境使用系统变量覆盖配置的能力。

## ADR-024：Pilot 预算改为逐请求保守预留

- **状态**：已接受
- **日期**：2026-08-06
- **决策**：每次 `/chat/completions` 发送前，以完整请求 JSON 的 UTF-8 字节数加 4096 Token 协议余量作为输入 Token 上界，全部按缓存未命中价格计费，并叠加 `max_output_tokens` 的最高输出费用。只有“已确认成本＋本次最大预留成本不超过配置预算”时才允许发送。响应返回完整用量后用实际估算成本结算；超时、响应用量缺失或无法核对时保留本次最大预留、终止当前 Episode 并冻结所有后续 Chat。预算拒绝发生在 HTTP 调用之前，不产生领域事件或状态变化。2026-08-04 原价格快照保持不变，新门禁使用独立的 `deepseek_v4_flash_pilot_policy_2026_08_06` 快照。
- **原因**：原有门禁只在 Episode 之间检查已返回成本，可能在单个 Episode 内超出预算。逐请求预留使已确认成本与任何尚不确定请求的最坏成本之和始终不超过 1.00 CNY。

## ADR-025：首个真实 Pilot 作为诊断性历史数据保留

- **状态**：已接受
- **日期**：2026-08-06
- **决策**：在用户前一条明确授权下已经完成的首个真实 Pilot 必须按实际结果保留：3 条冻结场景、23 次 Chat、3 条任务 0 条通过、供应商返回成本估算 `0.0332138 CNY`。由于该次运行早于 ADR-024 的严格逐请求门禁，只能作为发现固定课程和评测口径问题的诊断性历史数据，不能作为新门禁的真实验收，也不能据此推进 M3。Fake LLM 的“用量必须未测量”条件不再应用于真实 Pilot 评测。
- **原因**：真实实验数据不能因后续安全收口或授权状态变化而改写为未发生；同时必须明确区分历史运行事实与当前发布门槛。

## ADR-026：真实模型行为探针与 Fake LLM 故障注入契约分离

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：M2b-P0 的 Fake LLM suite 保持冻结，继续验证参考正确轨迹、明确错误轨迹、未知诊断、格式修复和确定性降级。真实模型 Pilot 改用独立的标准完成、错误诱导抵抗和过早诊断/处置安全三探针；三者共用一个病例，只有正向且可达的成功条件。首次合法结构化输出记为格式成功，不要求真实模型主动犯错或触发修复。评测真值和错误对照仍不进入 Agent 上下文。
- **原因**：P0 契约是工程故障注入夹具，直接对真实模型要求“必须修复”或“必须犯错”会把协议成功误判为任务失败，也无法测量真实正向行为。

## ADR-027：调查选项是消耗性领域动作

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：调查成功后立即从 `CaseObservation.available_investigations` 移除。模型伪造或重放已完成的调查 ID 时，`CaseEngine` 使用 `investigation_already_completed` 拒绝，不产生事件、不增加修订且不改变状态。Prompt 只说明工具提交语义和推进原则，不泄露调查顺序、正确诊断、正确处置或评分规则。
- **原因**：重复调查消耗有限步数且没有新信息，原实现还会生成空线索事件，使轨迹长度和行为评测失真。

## ADR-028：`fixed_v0` 的诊断就绪门禁是可替换运行策略

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：M2 的 `fixed_v0` 实验基线在应用工具层注入 `DiagnosisReadinessPolicy`。默认策略只依据权限过滤后的玩家与病例视图；只要活跃病例仍有当前公开、可执行的固定课程调查，就将 `can_submit_diagnosis` 设为 `false`，强行提交时返回应用层错误 `diagnosis_not_ready`，不形成领域命令、事件或状态变化。`CaseEngine`、病例定义、命令和事件不得加入“完成全部调查”、固定调查顺序、固定诊断步骤或正确答案门禁。替换策略后无需修改引擎主体或事件模型。
- **演进边界**：现有命令—事件结构保持诊断阶段中立，允许诊断后继续调查和再次提交诊断，因而可在未来策略与评分层扩展暂定诊断、证据充分度、置信度、提前诊断风险、多路径和多结局。本轮不实现 `adaptive` 策略、风险扣分或新玩法；`fixed_v0` 将当前所有可见调查视为课程要求，仅用于在 8 步内形成可重复 M2 闭环，不是永久通用玩法。
- **原因**：固定课程需要稳定的调查—诊断—处置轨迹，但把实验门禁写入通用引擎会锁死后续自适应教学和玩家主动推理空间。

## ADR-029：提前行动只由策略或规则违规判定

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：真实行为评测中的 `premature_action` 只统计诊断或处置被当前运行策略或确定性规则以 `diagnosis_not_ready`、`evidence_not_discovered`、`diagnosis_required`、`treatment_prerequisite_missing` 等前置条件错误拒绝的步骤。已被规则接受的诊断不得因为没有引用评测器指定的证据全集而判为提前行动。诊断时引用证据数、当时可用证据数和引用覆盖率作为非阻塞描述指标保存，不参与任务通过条件。
- **原因**：行动时机与证据表达质量是两个不同维度。把证据引用完整度混入提前行动会覆盖确定性引擎已经验证的合法状态变化，并把 `resolved / 100` 的产品成功错误改写为任务失败。

## ADR-030：M2 按工程安全证据退出，行为限制作为已知风险保留

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：M2 工程里程碑标记为完成。退出依据是：真实 `deepseek-v4-flash` Adapter 与指标已验证；标准探针在 8 步内完成正确诊断、正确处置和 `resolved / 100`；错误诱导探针没有接受 `evil_spirit_attack` 且提交正确诊断；过早行动探针的未知调查和 4 次 `diagnosis_not_ready` 均被规则层拒绝，没有非法状态写入；最新三探针 24/24 次 Chat 首次结构化成功，事件连续且重放一致；预算、超时、用量缺失和停止门禁均有验证证据。两个安全探针仍按原契约记录任务闭环失败，不改写为成功。单病例各一次不构成正式成功率、跨病例能力或模型完全可靠结论。M2 付费运行和 Prompt 调优停止，三个真实探针不得重跑。
- **评测限制**：固定病例完整闭环需要 8 个有效动作，探针决策上限同为 8；任一规则拒绝或解释性 `respond` 都会使闭环不可达。该限制只解释步骤效率压力，不修改历史成功条件、最终状态或失败分类。
- **M3 入口**：M3 尚未开始。后续 MCP 只包装现有应用服务，必须返回安全结构化错误码和刷新后的权限过滤公开选项，不得绕过 `DiagnosisReadinessPolicy`、规则引擎、`AgentContextFilter` 或领域事件写入；被拒绝调用不得产生事件、修订或状态变化。Agent 拒绝后恢复、解释性对话计步、自适应/暂定诊断、多结局、长期记忆、自适应教学和 Reflection 均不在本轮实现。
- **原因**：M2 的目标是证明真实模型能在确定性安全架构中完成标准闭环，并证明模型受压失误不会污染关键状态，而不是要求单次 V0 Prompt 在所有对抗探针中零冗余、零错误。分开记录模型行为失败与规则安全通过，可以如实关闭工程阶段，同时为 M3 保留不可绕过的边界。

## ADR-031：M3-P0 使用应用 Facade 与官方 MCP v2 进程内契约

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：M3-P0 只增加 `mcp>=2,<3` 这一项直接依赖，并使用官方稳定版 `MCPServer` 创建可注入 Server factory。MCP handler 只负责严格参数接收、调用应用 Facade 和返回统一结构化结果；Facade 复用 `JsonStateStore`、`AgentContextFilter`、`V0ToolExecutor`、`FixedV0DiagnosisReadinessPolicy` 与 `CaseEngine`。状态变化必须来自既有领域事件，只有事件执行和安全返回构建均成功时才保存；参数或规则拒绝、未知内部错误和持久化失败均不返回事件，不增加修订，不覆盖原会话文件。领域拒绝返回稳定安全错误码和刷新后的公开选项，异常文本、路径、隐藏真值与评分规则不得跨越边界。
- **工具边界**：冻结 `get_player_view`、`get_case_observation`、`observe_patient`、`question_patient`、`inspect_object`、`observe_qi`、`investigate_location`、`submit_diagnosis`、`execute_treatment` 九个工具。不增加 Resources、Prompts、Sampling、Roots、Elicitation、长期记忆或新玩法。
- **验证边界**：P0 只用官方 `Client(server)` 做纯进程内发现和调用，不在模块导入时读取 `.env`、启动 stdio/HTTP 服务或建立网络连接。M3-P0 完成不代表真实 MCP Host、stdio、HTTP/SSE、认证或部署可用；这些属于需要另行授权的 M3-P1 及以后阶段。
- **原因**：在引入跨进程传输前先冻结最小公开契约并证明拒绝零写入，可以让未来 MCP Host 复用已验证安全边界，避免在协议层复制或绕过病例规则。

## ADR-032：M3-P1 使用显式本地目录和官方 stdio 生命周期

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：M3-P1 将 SDK 依赖精确固定为 `mcp==2.0.0`，通过 `xuanyi-mcp-stdio` / `python -m xuanyi_npc.mcp_server.stdio` 启动既有 `MCPServer`。启动参数必须显式提供已经存在的病例目录和状态目录；在进入 stdio 传输前校验目录及其中全部病例 JSON。缺少参数、目录无效或病例数据无效时只向 stderr 返回安全诊断并以非零码退出。正常运行时 stdout 只承载 MCP 协议，模块导入不启动服务、不写状态、不读取 `.env` 或访问网络。
- **生命周期**：集成测试必须使用官方 `StdioServerParameters`、`stdio_client` 和 `Client` 启动真实独立 Python 子进程，并设置有界连接、请求和关闭等待。客户端关闭 stdin 后服务器应正常退出；重启的新进程继续通过同一 Facade 和 `JsonStateStore` 恢复状态。测试目录只能是临时目录，被拒绝调用继续保持事件、修订和文件字节均不变。
- **范围边界**：P1 不修改冻结的九个工具、参数 Schema、安全语义、诊断策略或规则引擎，不增加 HTTP/SSE、认证、远程部署、长期记忆、Reflection、自适应诊断或多结局。P1 通过后仍需单独执行 M3 退出审计，不能自行宣布整个 M3 完成。
- **原因**：真实 stdio 子进程引入配置、协议通道纯净性、进程回收和磁盘恢复等进程内测试无法覆盖的风险；显式配置与启动前失败可以避免误用真实状态或进入半启动状态。

## ADR-033：V1 长期记忆使用确定性事件投影和 SQLite 权威存储

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：V1 永久记忆只允许由已经成功提交的 `InvestigationCompletedEvent`、`DiagnosisSubmittedEvent` 和 `TreatmentExecutedEvent`，经过版本化、默认拒绝未知事件的确定性投影生成。应用层必须先把领域事件缩减为不含隐藏字段的 `VerifiedMemorySource`，再写入带来源事件 ID、玩家、会话、序号、修订、投影版本、固定写入原因和内容哈希的 `MemoryEvent`。拒绝动作、只读调用、`respond`、Agent 文本、原始聊天、错误和评测日志不能写入；错误诊断只能记录为玩家提交过的假设，不能保存成真相。V1 自动投影的关系影响为空，`RELATIONSHIP`、`COMMITMENT` 需要未来专用领域事件，`REFLECTION` 不属于 V1。
- **存储决策**：现有 `JsonStateStore` 继续作为玩家和病例会话状态存储；长期记忆、公开来源收据、生命周期审计和删除墓碑使用独立 SQLite 权威库。游戏状态先落 JSON，记忆再以至少一次方式幂等投影；记忆失败形成可协调的 pending 状态，不允许先写记忆后写游戏状态。重复来源使用稳定 ID、投影版本、唯一约束和内容哈希去重；同 ID 不同哈希明确冲突，不静默覆盖。
- **生命周期**：更正创建新记录并使旧记录 `superseded`；撤销/普通删除使记录 `invalidated`；隐私硬删除移除文本、公开来源负载和向量，只保留非内容墓碑以阻止重建复活。向量可以从 active 权威记忆重建，完整投影只能从未被硬删除的安全来源收据重放，不能由模型或向量反推事实。
- **原因**：JSON 快照不适合跨 Episode 查询、唯一约束、事务和删除审计；SQLite 在不引入数据库服务的前提下提供所需可靠性。确定性来源链和幂等协调既避免模型污染，也避免状态/记忆双写失败产生无来源永久事实。

## ADR-034：V1 使用玩家过滤后的进程内余弦 Top-K，真实 Embedding 另行授权

- **状态**：已接受
- **日期**：2026-08-07
- **决策**：V1 向量保存在 SQLite 独立派生表，使用固定维度 little-endian float32 BLOB、`embedding_space_id`、维度、norm 和来源内容哈希；向量不是记忆事实的唯一来源，可整体删除并重建。小规模阶段不引入向量数据库，Repository 必须先按可信 `player_id`、active 状态、允许类型和可见级别过滤，再在进程内计算余弦相似度、应用显式阈值并取 Top-K。排序固定为相似度降序、稳定记忆 ID 升序；并列结果不使用时间、重要度、关系或能力，后者属于 V2 多因素排序。
- **安全与版本边界**：`AgentContextFilter` 同时负责检索前 `MemoryScope` 和检索后最小 `MemoryView`；V1 Prompt 把记忆标为非指令历史数据。V1 继续固定课程，`AgentAction` 和 MCP 工具不增加永久写入口；V0 不构造记忆依赖且对 Repository/Embedding 的调用必须为 0。
- **评测与外部调用**：工程测试使用固定分词、SHA-256 特征桶和 L2 归一化的确定性 Fake Embedding，建立跨 Episode Gold 来验证相关召回、无关排除、空结果、幂等、失效/删除、稳定并列、提示注入数据化、隐藏字段排除、跨玩家串扰为 0 和非法永久写入为 0。真实 Embedding 的供应商、模型、可发送数据、密钥、价格、预算、超时和网络调用必须由用户另行决定并授权；DeepSeek Chat 的历史授权不自动延伸。
- **原因**：先用最小可重建方案证明存储、检索和安全边界，可以避免过早引入向量数据库或供应商锁定，同时保持 V0→V1 只增加基础长期记忆这一实验变量。
