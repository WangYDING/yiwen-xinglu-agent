# Agent 版本边界

V0、V1、V2 共用同一套确定性病例引擎、权限过滤视图、`AgentAction` Schema 和 `EpisodeResult`。版本升级只能增加明确列出的能力，不能改变病例真相或绕过领域规则。

| 能力 | V0（M2a/M2b-P0/P1） | V1 | V2 |
|---|---|---|---|
| 当前回合短期上下文 | 有 | 有 | 有 |
| 结构化 `AgentAction` | 有 | 有 | 有 |
| 基础病例工具调用 | 有 | 有 | 有 |
| `AgentContextFilter` | 强制开启 | 强制开启 | 强制开启 |
| 课程策略 | 固定 | 固定 | 自适应 |
| 跨回合长期记忆检索 | 无 | 基础向量 Top-K | 多因素排序 |
| 记忆排序因子 | 无 | 向量相似度 | 相关性、重要性、时间新近度等 |
| 基于历史的能力画像 | 无 | 只读取已验证记忆 | 有 |
| Reflection | 无 | 无 | 有 |
| 直接修改关系、技能、病例状态 | 禁止 | 禁止 | 禁止 |
| 模型直接写入永久记忆 | 禁止 | 禁止 | 禁止 |

## M2 已完成 V0 工程闭环，并拆分为 M2a/M2b-P0/M2b-P1a/P1b

- 固定课程和固定提示策略；
- Pydantic 校验的 `AgentAction`；
- 读取权限过滤后的 `PlayerView` 和 `CaseObservation`；
- 调用观察、询问、验物、观炁、调查地点、提交诊断和执行处置等基础工具；
- 统一输出 `EpisodeResult`；
- 格式错误重试、规则拒绝和最大步骤终止。
- Fake LLM 完整 Episode、事件连续性和重放一致性。
- 公开诊断候选、调查说明和处置说明；正确性、结果和隐藏门槛不进入 Agent 上下文。

M2a/M2b-P0/P1a/P1b 均不实现：

- 跨 Episode 长期记忆；
- 基于历史错误的自适应教学；
- 关系或技能的自动成长；
- Reflection 或高层记忆总结；
- 模型可调用的永久记忆写入工具；
- 患者、灵体等额外 Agent。
- 可运行的 stdio/HTTP MCP 服务、界面或多 Agent 编排。

## M3 边界

M3-P0/P1 已按以下边界把现有应用服务包装为最小 MCP 工具，并验证本地 stdio 子进程生命周期：

- 返回安全、结构化错误码（例如 `diagnosis_not_ready`）和刷新后的权限过滤公开选项；
- 不得绕过 `DiagnosisReadinessPolicy`、规则引擎、`AgentContextFilter` 或领域事件写入；
- 被拒绝工具调用不得产生事件、修订或状态变化；
- 不在 MCP 层修改解释性对话是否消耗行动步数，也不实现拒绝后的新 Agent 策略；
- 不加入自适应诊断、暂定诊断、多结局、长期记忆、自适应教学或 Reflection。

## 权限过滤边界

模型调用前只能构建以下只读对象：

- `PlayerView`：玩家公开身份、教学阶段和已解锁技能；不包含三维关系原始值、锁定技能和技能前置条件。
- `CaseObservation`：病例公开信息、已经发现的线索、公开诊断候选和当前合法选项。公开候选只包含 ID 与中立说明，不标记正确性；对象不包含根因、因果链、未发现线索、合法诊断集合、处置结果、评分规则和隐藏门槛。
- `AgentAction`：回复或基础工具请求；不包含状态变化、技能解锁或永久记忆字段。

权限检查发生在检索和 Prompt 拼装之前，不能依靠系统提示词要求模型“看见但不要泄漏”。

三个产品版本始终保留 `AgentContextFilter`。不能为了消融实验创建关闭过滤的 V0、V1 或 V2 产品配置。

## A4 安全消融

“只靠提示词保密 vs. 程序化权限过滤”编号为独立的 A4 安全消融，不属于 V0/V1/V2 产品版本。

A4 的不安全对照只能：

- 在离线评测进程中运行；
- 使用专门的合成病例和无真实用户数据夹具；
- 禁止连接生产存储、永久记忆或外部动作；
- 在结果中标记为 `production_eligible = false`；
- 运行后销毁隔离状态，不生成可恢复到产品的存档。

A4 只用于量化程序化过滤的安全价值，不能成为可部署配置。

## 永久记忆写入策略

永久记忆采用单向管道：

```text
已验证玩家/世界动作
→ 确定性领域事件
→ 记忆投影与写入策略
→ MemoryEvent
→ 持久化
```

模型可以在未来提供摘要文本候选，但候选文本本身不是永久状态。只有已经通过领域规则校验、包含来源事件和写入原因的记忆事件才能进入存储。`record_memory` 不属于 Agent 可调用工具。

## M4 的 V1 记忆边界

M4-P0 冻结规划，P1–P4 与退出审计均已完成；具体契约见 `M4_MEMORY_PLAN.md`、`M4_MEMORY_EVALUATION_PLAN.md` 和 `M4_EXIT_AUDIT.md`。后续实现必须保持：

- 自动投影初始只允许成功的 `InvestigationCompletedEvent`、`DiagnosisSubmittedEvent` 和 `TreatmentExecutedEvent`；未知事件默认不投影；
- 调查、诊断和处置分别只保存权限过滤后的公开经历，不能保存正确性、数值评分、根因、未发现线索或隐藏门槛；错误诊断只记为“曾提交的假设”；
- V1 自动记忆只能使用 `EPISODIC` 和受病例范围约束的 `LEARNING`；`RELATIONSHIP`、`COMMITMENT` 需要未来专用领域事件，`REFLECTION` 只属于 V2；
- SQLite 是长期记忆和来源链的权威存储，向量是独立、可删除和可重建的派生数据；当前 JSON 继续保存 V0 玩家/病例状态；
- 检索前先以可信 `player_id` 和权限过滤候选，再做余弦相似度 Top-K；V1 不使用重要度、时间、关系或能力进行排序；
- 检索后只把最小 `MemoryView` 放入 Prompt 的非指令历史数据区域；恶意文本仍是数据，不能改变工具、课程或结构化行动；
- V0 不构造记忆依赖且读取次数为 0；V1 `AgentAction` 和 MCP 工具保持没有永久写入能力；
- 真实 Embedding 不继承 DeepSeek Chat 的历史授权，供应商、数据范围、预算、密钥和网络调用必须另行确认。

V1 的记忆只补充上下文，不能暗中改变固定课程、`fixed_v0` 诊断策略、关系、能力、技能或权限。M4-P3 已用独立 `V1DoctorAgentInput` 和 Prompt `v1.0.0` 接入只读记忆：可信 `MemoryScope` 在排序前排除当前 Episode 和非允许类型，检索后再缩减为仅含不透明 ID、类型、公开内容和时间的 `MemoryView`。记忆固定作为用户消息中的 `retrieved_memories` JSON 数据，不能改变消息角色、工具、课程或 `AgentAction`。

`ready` 表示检索成功且有合法历史，`empty` 表示完整索引中没有达到阈值的合法历史，两者均可继续 V1 决策；`unavailable` 表示索引缺失/过期、存储/检索失败或权限异常，必须返回 `memory_context_unavailable` 并在 LLM 调用前停止。该离线检查点没有使用真实 LLM，只能证明程序化过滤和消息结构保持，不能证明真实模型已抵抗记忆提示注入。

## M4.5 终止后的 V1 发布边界

M4.5 的本地 Dense-only 结果没有达到真实 V1 Prompt 准入线。因此当前代码中已存在的 V1 记忆上下文只能视为经过离线工程验证的实验能力，产品运行默认关闭：

- 正式 Agent 模式不得把语义检索结果注入 Prompt；
- 可选 `shadow` 模式只能记录权限过滤后的检索候选与状态，输出不会成为模型消息、工具参数、课程输入或状态命令；
- shadow 失败不改变病例流程，也不能伪装成“玩家没有历史”；
- M5 的跨病例反应只读取确定性 CampaignEvent/CampaignFact，不读取 BGE 排名；
- 模型仍没有永久记忆写入、删除或更正工具；
- 真实多病例轨迹形成前，不重新进行阈值调优、reranker 或其他模型比较。

这里的“关闭”是产品装配决策，不删除 M4 已验证的存储、检索、权限过滤和 V1 Prompt 代码，也不改写 M4.5 的真实负结果。
