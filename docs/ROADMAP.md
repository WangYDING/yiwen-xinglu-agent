## M0～M6 历史结论与新的产品主线

M0～M6 的代码、提交、验证记录和正负实验全部保留，不因本次主题回归而改写。它们证明了确定性病例、Agent/MCP 安全边界、记忆工程、真实失败分析、三病例切片、CLI、打包和本地发布准备；它们没有证明最初设想的“师承型导师 NPC”已经完成。

在继续 M6-P3/P4 或任何公开发布前，项目按以下顺序推进。每一步都必须产生可玩或可审计的真实证据，不能用配置枚举、空数据结构或测试数量冒充产品能力。

| 顺序 | 产品主线 | 当前状态 | 最小产物与退出条件 |
|---|---|---|---|
| A | 导师教学闭环 | **下一阶段唯一允许实现** | 选现有一案，玩家亲自行动；导师完成案前目标、事件后观察、一次规则控制提示和案后反馈；导师不操作病例；无 LLM 可运行、可恢复、可重放 |
| B | 技能与三维关系更新 | 未开始 | 已提交教学证据确定性更新一个技能维度及亲近/信任/认可；来源可追溯、重复结算幂等、LLM 零写入 |
| C | 课程、补课、考试和晋级 | 未开始 | 固定课程资格、补课条件、一次考试和阶段更新形成完整可玩事件链；之后才考虑自适应课程 |
| D | 权限与一条完整传承链 | 未开始 | 知识→课程→考试→能力/关系/承诺→传承开放的多条件确定性链，可解释且可重放 |

## M2a 完成边界

M2a 证明以下工程性质：

- Agent 只接收 `PlayerView`、`CaseObservation`、最近有限消息和固定课程；
- 公开诊断词表、调查说明和处置说明提供可提交语义，但不携带正确性、结果、评分或隐藏门槛；
- `AgentAction` 必须通过 Pydantic 校验；首次格式错误只修复一次，再失败安全降级；
- 工具层只把建议翻译为领域命令，关键状态只能由规则引擎和领域事件修改；
- 已知错误诊断可正常提交并计为错误，未知诊断被拒绝且不改变状态；
- Fake LLM Episode 有最大步骤、连续事件、统一记录和可重放终态。
