# M5 多病例游戏纵向切片规划

> **当前状态（2026-08-10）**：P0、P1 与 P2 已完成；交互式 CLI 已自动发现并独立运行旧纸伞、灰灶客栈和月井回声三个病例。P3 的确定性跨 Episode 连续性尚未开始。

## 1. 产品目标

M5 让普通用户用同一个玩家身份，连续完成“旧纸伞与失约书生”和两个新病例；退出程序并重新启动后仍能继续。后续病例会以公开、确定、可解释的方式响应此前真实事件，但任何病例都不能依赖未通过准入的 Dense 语义检索才能完成。

M5 同时服务两类作品集目标：

- Agent 应用岗：展示结构化行动、工具/MCP、安全编排、事件投影、持久化、可回放、模型模式隔离和 shadow RAG 评测；
- 游戏 AI 产品岗：展示三个可玩病例、跨病例连续体验、NPC 对玩家历史的反应、成长反馈、普通用户入口和真实试玩证据。

M0–M4.5 形成了 Agent 工程基础；M5 开始补齐游戏 AI 产品纵向切片。既有 Agent 证据与真实负结果都保留，合成检索指标不得描述为游戏效果或玩家收益。

## 2. 玩家流程

```text
启动交互式 CLI
→ 创建或选择玩家
→ 查看病例列表及继续状态
→ 开始新 Episode 或恢复未完成 Episode
→ 查看公开观察与合法行动
→ 调查、诊断、处置
→ 保存病例事件与玩家进度
→ 完成后查看师评和公开历史影响
→ 进入下一病例，或退出后重启继续
```

用户不需要运行 pytest、评测脚本或直接编辑 JSON。网页界面不属于 M5 最小范围，交互式 CLI 是第一个普通用户入口。

## 3. 架构边界

### 3.1 复用现有能力

M5 继续复用 `CaseDefinition`、`CaseSessionState`、`CaseEngine`、领域事件、事件重放、`JsonStateStore`、`AgentContextFilter`、`V0ToolExecutor`、可替换诊断就绪策略、`EpisodeResult` 和冻结的 MCP 安全语义。病例引擎不加入固定调查顺序、正确答案或跨病例特例。

现有 `PlayerState.handled_case_ids` 可以承载已完成病例摘要，但更新必须来自新的确定性应用/领域事件边界，不能由 UI、Agent 或语义检索直接写入。

### 3.2 计划新增的产品边界

M5-P1/P3 计划引入以下最小职责，名称可在实现前按现有模块命名调整，语义不得合并到 UI：

- `CaseCatalog`：从显式病例目录加载、校验并列出病例，只返回公开目录信息；
- `CampaignState`：按 `player_id` 保存当前 Episode、已完成病例、公开跨案事实和修订；
- `CampaignEvent`：记录开始、继续、完成 Episode，以及经过规则确认的公开跨案影响和玩家成长；可从初始状态重放；
- `CampaignFact`：从已提交病例事件确定性投影的玩家公开历史，包含来源病例、会话、事件序号、投影版本和固定事实类型；
- `CrossEpisodeRule`：只读取可信 `CampaignState` 与公开病例钩子，输出对话变体、公开提示、可选行动 ID 或预先定义的知识/技能/关系变化事件；不得修改病例真相、正确诊断、评分或隐藏门槛；
- `MultiCaseEpisodeService`：统一创建/选择玩家、列出病例、开始/恢复 Episode、执行行动、完成收口和保存；CLI 只调用此服务。

### 3.3 提交、故障和恢复顺序

一次合法病例动作仍先由 `CaseEngine` 产生领域事件，再原子保存病例会话。病例完成后的跨案状态按以下顺序处理：

```text
病例会话和事件成功保存
→ 确定性生成 CampaignEvent / CampaignFact
→ 保存玩家与 CampaignState
→ 返回刷新后的公开视图
```

不伪造 JSON 文件之间的分布式事务。病例保存失败时跨案写入必须为 0；病例已保存而跨案投影失败时返回明确 `campaign_projection_pending`，并由只读取已提交事件的显式协调入口幂等补齐。重复协调不得重复完成病例或重复改变关系/技能。拒绝动作不产生病例事件、CampaignEvent、修订或文件变化。

### 3.4 确定性游戏记忆与语义记忆

M5 正式使用的“记住”是确定性游戏记忆：

- 来源是明确、已提交的病例与 CampaignEvent；
- 内容是结构化公开事实，例如处理过的病例、公开处置、已履行承诺、确定性解锁的知识或关系变化；
- 可直接驱动后续公开对话、提示和合法选项；
- 规则、来源和重放结果可审计。

语义向量记忆默认关闭，不进入 Agent Prompt，不影响行动或玩家状态。可选 shadow mode 只能在权限过滤后记录检索候选与诊断状态，供离线分析；正式玩法始终可以在没有 BGE、没有 SQLite 向量和没有 LLM 时完成。

## 4. Episode Runner 接口规划

M5-P1 的应用服务面向 CLI 提供固定操作，而不是接受任意脚本或文件路径：

| 操作 | 输入 | 公开结果 | 状态规则 |
|---|---|---|---|
| `create_player` | 显示名 | 新玩家摘要 | 唯一稳定 `player_id`，原子保存 |
| `list_players` | 无 | 可选择玩家列表 | 只读 |
| `list_cases` | 可信玩家 | 病例标题、状态、可玩原因 | 只读，不泄露真值 |
| `start_episode` | 玩家、公开病例 ID | 初始公开观察 | 拒绝重复活跃会话和越权病例 |
| `resume_episode` | 玩家、会话 ID | 恢复后的公开观察 | 校验玩家/病例/会话一致 |
| `submit_action` | 既有 `AgentAction` 或 CLI 选择 | 安全结果、事件序号、刷新视图 | 只由规则事件改变状态 |
| `finish_episode` | 已完成会话 | 公开结局、师评、下一可玩病例 | 幂等投影 CampaignState |
| `quit` | 当前玩家/会话 | 已保存确认 | 不生成游戏事件 |

所有返回使用严格结构化契约，至少区分 `ok`、稳定错误码、安全消息、玩家/会话修订和刷新后的公开视图。状态损坏、病例缺失、玩家不匹配、重复完成和协调待处理必须明确失败，不能进入半启动或静默丢进度状态。

CLI 计划采用菜单与编号选择，仍允许展示底层公开 ID 以便调试；日志进入单独诊断通道，普通输出不显示文件路径、异常堆栈、隐藏真值或密钥。

## 5. 两个新病例概要

以下概要已在 M5-P2 落地为正式病例 JSON；完整公开/隐藏字段审计、稳定 ID 和参考轨迹见 `docs/M5_CASE_DESIGN.md`。P3 跨案钩子仍只是设计候选，没有进入当前运行逻辑。

### 5.1 病例二：灰灶客栈与无火炊烟

- 玩法目标：从患者问询扩展到环境链调查；区分“出现灵异现象”和“灵体具有恶意”；让玩家在多个合法调查路径中组合证据。
- 表面问题：客栈炉火看似正常，饭食却反复变冷，灶灰会在无人时留下逆风痕迹。
- 调查面：观察掌勺人、询问店主、检查灶台与公开符记、观炁、调查烟道/灰痕。
- 公开假设方向：恶意灰祟、普通燃料问题、灶契错置或通路受阻；词表同时保留合理错误项。
- 处置方向：修复公开通路并归还错置契物、强行驱逐、只压制冷炁；只有确定性规则决定结果。
- 作品目标：证明新病例能复用现有 Schema/引擎、拥有非固定测试轨迹，并安全承接旧纸伞案的公开历史反应。
- 跨案钩子：若玩家在旧纸伞案履行公开承诺并采用解决根因的处置，道医开场会明确引用这一公开经历，并可提供一条不影响必需路径的“先查契物归属”提示；否则使用中性开场。病例真相和基础可完成路径不变。

### 5.2 病例三：月井回声与错投木简

- 玩法目标：验证证人陈述、物件与地点证据的交叉核对；让上一案的公开选择改变 NPC 反馈或可选调查，而不替玩家给出答案。
- 表面问题：送信人尚未开口，井中就先响起与其相似的回答；他开始回避一口月井。
- 调查面：观察送信人、询问行程、检查公开木简与系绳、观炁、调查月井、询问见证人。
- 公开假设方向：恶意回声实体、紧张导致的模仿错觉、消息回响错绑到收信人；词表同时保留合理错误项。
- 处置方向：按公开证据完成正确交接、封住井口、毁掉木简；结果由确定性规则决定。
- 作品目标：证明三个 Episode 形成连续但可独立回放的游戏体验，并展示 NPC 对玩家处理环境契约与承诺方式的稳定反应。
- 跨案钩子：病例二若以修复通路和归还契物解决，道医或见证人开放一条可选的“核对交接顺序”调查；其他公开结果使用另一条中性调查。两条路径都能取得完成病例所需证据，避免把旧选择变成隐藏软锁。

所有病症、物件和处置均为架空内容，不生成现实诊断、处方或剂量。

## 7. M5 最低验收

1. 一个新玩家可以依次完成三个病例；
2. 每个病例允许多种合法调查选择，不是硬编码的评测轨迹；
3. 至少两个后续场景会响应此前实际提交的公开事件；
4. 退出进程并重启后能恢复未完成 Episode 和已完成进度；
5. 所有病例事件与 CampaignEvent 序号连续且可重放到相同终态；
6. 不同玩家的会话、历史反应和进度完全隔离；
7. 参数错误、规则拒绝和重复操作不产生事件、修订或文件变化；
8. 三病例无 LLM 路径可以完整运行；
9. 普通用户可按 README 启动交互式 CLI，不需要运行测试脚本；
10. 有一份从创建玩家到第三案结局的演示脚本或录屏方案；
11. 报告分别列出 Agent 应用岗与游戏 AI 产品岗证据，不把合成 Gold 当玩家效果；
12. 语义向量记忆默认关闭，shadow mode 不进入 Prompt 且不改变行动或状态。
13. 至少一项玩家知识、技能或公开关系进展由完成病例后的确定性事件产生，并可在重启后恢复和重放。

## 9. P3 前决策状态

M5-P1/P2 已按冻结边界完成。进入 M5-P3 前没有引擎级阻塞，但需要单独授权确定性 Campaign 事件、至少一项可见成长和跨案文案的实现。

病例文件当前固定为可回归内容；P3 可以引用本文预留的公开钩子，但不得修改病例真值、正确诊断或基础可完成路径。网页样式、最终项目名称、真实 DeepSeek 预算和是否录制真实模型试玩仍留待对应阶段单独决定。
