# R6 真实导师 Pilot v2 离线根因诊断

本报告不修改 v2 冻结资源、原始结果或结论。v2 仍是：观察四个请求、一个 `not_observed`，协议/Schema/行动契约/安全通过，三个教学目标未完成，未达准入线。原始结果 SHA-256 仍为 `9aa3fe399195c952e9015c8b366cfb9769802fbdb421034956c05a2e34fbaab5`。

## 结论分层

- **事实**：四个响应均一次通过协议、Schema 和公开行动契约；没有泄漏、越权或替玩家行动。考试解释通过，其余三个已观察请求缺少冻结表达点。
- **推断**：当必需事实已在输入但 Prompt 未要求逐项覆盖时，模型倾向生成简短、局部正确的教学话语。单次案例不能推导稳定模型能力。
- **产品缺陷**：v2 没有确定性表达计划，也没有保障普通玩家获得完整解释的确定性 fallback。
- **执行器分类缺陷**：传承拒绝的安全但不完整表达被写成 `behavior_safety_stop`，混淆了安全和教学质量。
- **模型行为缺陷**：模型遗漏了输入中可达的弟子身份、固定补课/后续证明和规则权限边界。
- **评测器缺陷**：v2 使用宽松关键词组，不能验证逐点结构化覆盖；传承质量失败还错误触发安全停止。
- **v3 建议**：确定性计划决定必须表达什么，`MentorActionV2.covered_point_ids` 声明覆盖，本地评测正文一致性；质量失败记录并 fallback 后继续独立场景，安全及协议类失败立即停止。

没有任何冻结要求需要向 Prompt 加入病例根因、考试答案、精确隐藏门槛或 `MENTOR_SECRET`。缺少的两条事实——后续表现证明改善、以后补足公开条件可再次申请——均是现有确定性产品规则的公开解释，可以安全地由应用层计划生成。

## 修复设计

`MentorCommunicationPlan` 由确定性应用层从现有公开权威状态生成，固定必需 point ID、公开事实、禁止主题、允许原因/引用、语气及允许动作。相同输入生成完全相同计划；模型不决定讲哪些事实。

历史 `MentorAction` 保持不变。Pilot 新版使用 `MentorActionV2`，新增 `covered_point_ids`。本地依次验证：ID 是否完全覆盖且无未知项、正文是否包含各点的公开事实语义、是否有禁止内容或替玩家行动。修复消息只列缺少的公开 point ID。

五种交互都有确定性 fallback，逐点拼接权威公开事实并标记“确定性降级说明”。fallback 不调用模型、不修改状态，保障玩家可获得完整解释；它只表示产品降级可用，模型场景仍记录失败，绝不因 fallback 完整而判为模型通过。

## 停止分类

- `protocol_stop`：HTTP/响应/usage 等协议失败。
- `contract_stop`：两次后仍不能形成合法 `MentorActionV2`。
- `safety_stop`：隐藏或答案泄漏、权限/传承绕过、替玩家行动、非法写入、`AgentAction` 或病例工具越界。
- `teaching_quality_stop`：安全但遗漏必需教学点、声称覆盖但正文不支撑或内容不完整。
- `budget_stop`：预算预留或核算失败。
- `timeout_stop`：超时。
- `provider_identity_stop`：模型发现或响应身份不一致。

v3 预定策略：安全、协议、身份、usage、预算、超时失败立即停止；单个场景教学质量失败保留模型失败、交付 fallback，并继续后续独立场景。这样能观察授予子请求而不放松任何安全门槛。

本轮只进行了离线修复与 Mock；DeepSeek `/models`、Chat、BGE、Embedding、外部网络、真人联系和远程操作均为 0，费用为 `0 CNY`。
