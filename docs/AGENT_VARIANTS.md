# Agent 版本边界

V0、V1、V2 共用同一套确定性病例引擎、权限过滤视图、`AgentAction` Schema 和 `EpisodeResult`。版本升级只能增加明确列出的能力，不能改变病例真相或绕过领域规则。

| 能力 | V0（M2a/M2b-P0/P1） | V1 | V2 |
|---|---|---|---|
| 当前回合短期上下文 | 有 | 有 | 有 |
| 结构化 `AgentAction` | 有 | 有 | 有 |
| 基础病例工具调用 | 有 | 有 | 有 |
| `AgentContextFilter` | 强制开启 | 强制开启 | 强制开启 |
| 课程策略 | 固定 | 固定 | 自适应 |
| 跨回合长期记忆检索 | 无 | 基础向量 Top-K | 多因素排序 |
| 记忆排序因子 | 无 | 向量相似度 | 相关性、重要性、时间新近度等 |
| 基于历史的能力画像 | 无 | 只读取已验证记忆 | 有 |
| Reflection | 无 | 无 | 有 |
| 直接修改关系、技能、病例状态 | 禁止 | 禁止 | 禁止 |
| 模型直接写入永久记忆 | 禁止 | 禁止 | 禁止 |

## M2 只实现 V0，并拆分为 M2a/M2b-P0/M2b-P1a/P1b

- 当前 Episode 内的短期对话上下文；
- 固定课程和固定提示策略；
- Pydantic 校验的 `AgentAction`；
- 读取权限过滤后的 `PlayerView` 和 `CaseObservation`；
- 调用观察、询问、验物、观炁、调查地点、提交诊断和执行处置等基础工具；
- 统一输出 `EpisodeResult`；
- 格式错误重试、规则拒绝和最大步骤终止。
- Fake LLM 完整 Episode、事件连续性和重放一致性。
- 公开诊断候选、调查说明和处置说明；正确性、结果和隐藏门槛不进入 Agent 上下文。

M2b-P0 已完成：

- 建立 3 条供应商无关的严格 dev 场景；
- 每条场景都有参考正确轨迹和明确错误轨迹；
- 确定性评测器只读取统一 `EpisodeResult`，分类任务结果、错误假设、规则拒绝和格式恢复；
- 一条本地命令验证安全上下文、最大步骤、连续事件与重放终态；
- Fake LLM 的真实延迟、Token、成本和成功率保持未测量。

M2b-P1a 已完成：

- DeepSeek `deepseek-v4-flash` 直接 HTTP `LLMAdapter` 与只读模型发现；
- 供应商无关用量、人民币价格快照和预算停止；
- MockTransport 覆盖请求、响应、错误、Token 和缓存计费；

M2b-P1b 真实模型行为评测收口中：

- 已查询当前 Key 可用模型，Flash 存在且未切换到 Pro 或旧别名；

- 已经完成脱敏轨迹的离线重评、重复调查拒绝和 Prompt 最小纠偏；下一次付费复核仍需单独授权。

M2a/M2b-P0/P1a/P1b 均不实现：

- 跨 Episode 长期记忆；
- 基于历史错误的自适应教学；
- 关系或技能的自动成长；
- Reflection 或高层记忆总结；
- 模型可调用的永久记忆写入工具；
- 患者、灵体等额外 Agent。
- MCP Server、界面或多 Agent 编排。

## 权限过滤边界

模型调用前只能构建以下只读对象：

- `PlayerView`：玩家公开身份、教学阶段和已解锁技能；不包含三维关系原始值、锁定技能和技能前置条件。
- `CaseObservation`：病例公开信息、已经发现的线索、公开诊断候选和当前合法选项。公开候选只包含 ID 与中立说明，不标记正确性；对象不包含根因、因果链、未发现线索、合法诊断集合、处置结果、评分规则和隐藏门槛。
- `AgentAction`：回复或基础工具请求；不包含状态变化、技能解锁或永久记忆字段。

权限检查发生在检索和 Prompt 拼装之前，不能依靠系统提示词要求模型“看见但不要泄漏”。

三个产品版本始终保留 `AgentContextFilter`。不能为了消融实验创建关闭过滤的 V0、V1 或 V2 产品配置。

## A4 安全消融

“只靠提示词保密 vs. 程序化权限过滤”编号为独立的 A4 安全消融，不属于 V0/V1/V2 产品版本。

A4 的不安全对照只能：

- 在离线评测进程中运行；
- 使用专门的合成病例和无真实用户数据夹具；
- 禁止连接生产存储、永久记忆或外部动作；
- 在结果中标记为 `production_eligible = false`；
- 运行后销毁隔离状态，不生成可恢复到产品的存档。

A4 只用于量化程序化过滤的安全价值，不能成为可部署配置。

## 永久记忆写入策略

永久记忆采用单向管道：

```text
已验证玩家/世界动作
→ 确定性领域事件
→ 记忆投影与写入策略
→ MemoryEvent
→ 持久化
```

模型可以在未来提供摘要文本候选，但候选文本本身不是永久状态。只有已经通过领域规则校验、包含来源事件和写入原因的记忆事件才能进入存储。`record_memory` 不属于 Agent 可调用工具。
