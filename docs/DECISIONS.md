# 架构决策记录

本文件记录会影响实现边界或后续返工成本的决策。新决策追加记录，不静默改写历史结论。

## ADR-001：确定性领域层拥有关键状态

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：病例真相、能力值、关系值、权限、动作合法性、技能解锁和最终状态修改只能由确定性领域层负责。Agent 只能输出经过校验的语言、工具请求或状态变化建议。
- **原因**：避免模型幻觉直接污染游戏状态，使行为可测试、可审计和可回放。

## ADR-002：M0 使用 Pydantic v2 和 `src` 布局

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：领域对象使用 Pydantic v2；项目采用 `src/xuanyi_npc` 包布局，测试使用 pytest。
- **原因**：Pydantic 同时提供运行时校验、JSON 序列化和后续结构化输出 Schema，`src` 布局可避免测试误用仓库根目录中的未安装模块。

## ADR-003：M0 使用原子 JSON 文件验证持久化接口

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：M0 仅为玩家状态和病例会话提供原子 JSON 保存/读取接口，运行数据写入被 Git 忽略的 `runtime_data`；SQLite 延后到需要事件查询和记忆检索时引入。
- **原因**：先验证模型边界和存储接口，避免在领域模型尚未稳定时绑定数据库表结构。

## ADR-004：首个病例是可替换的技术夹具

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：“旧纸伞与失约书生”仅用于验证线索、调查、误导、诊断、处置和评分结构，不作为最终世界观承诺。患者和灵体在垂直切片阶段不是独立 Agent。
- **原因**：优先完成一个可测试闭环，减少世界观未决事项对工程进度的阻塞。

## ADR-005：MCP 不包含业务规则

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：后续 MCP 工具只调用应用服务；动作校验和状态更新继续由领域层实现，不在 MCP Server 中复制规则。
- **原因**：保证命令行、测试、未来界面和 MCP 共用同一套确定性行为。

## ADR-006：M1 使用命令—事件—新状态执行模型

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：`CaseEngine.execute()` 接收病例、玩家、当前会话和一个带时区时间戳的结构化命令，返回新会话、领域事件及用户可见结果。引擎不原地修改输入；失败通过具体 `RuleViolation` 子类型返回，且不产生部分状态。
- **原因**：保证同样输入得到相同结果，并为后续日志、MCP 工具、回放和故障分析提供稳定边界。

## ADR-007：M1 的病例评分保持确定且可解释

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：当前总分由已发现关键线索占比、诊断正确分、根因处置分和危险处置惩罚构成，并限制在病例配置的最高分内。提示扣分、心性评价、技能成长和关系变化推迟到教学阶段。
- **原因**：先验证病例过程与结果的评分闭环，避免在教学和关系规则确定前混合多个尚未实现的维度。

## ADR-008：Agent 上下文采用检索前最小权限视图

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：模型只能接收 `PlayerView` 与 `CaseObservation`。视图构建时只加入当前已经解锁或发现的内容，并移除病例根因、因果链、未发现线索、隐藏信息、合法诊断集合、处置结果、评分规则、技能前置条件及关系原始值。
- **原因**：秘密不能在进入 Prompt 后再依赖提示词保护；未授权内容必须在模型调用前从数据层移除。

## ADR-009：V0、V1、V2 共用 EpisodeResult 并采用递增能力边界

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：V0 使用短期上下文、固定课程、结构化行动和基础工具；V1 只在 V0 上增加经过验证的跨回合记忆；V2 再增加自适应教学和 Reflection。三个版本共用 `EpisodeResult`，确保后续对比实验的输出结构一致。
- **原因**：避免版本间同时改变多个变量，使记忆和教学能力的增益能够通过真实消融实验复核。

## ADR-010：模型不能直接提交永久记忆或关键状态

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：从 Agent 工具集合移除永久 `record_memory`，并从 `AgentAction` 移除关系、技能状态变化提议。未来永久记忆必须由已验证领域事件经过记忆投影策略生成；模型文本最多作为待验证候选内容。
- **原因**：防止提示注入、幻觉或工具误用直接污染长期状态，并保留记忆来源以供审计。

## ADR-011：事件重放是状态一致性的发布门槛

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：病例引擎产生的事件必须能够从同一初始 `CaseSessionState` 重建完全相同的最终状态；事件序号断裂、会话不匹配、结束后事件和无证据诊断事件必须拒绝重放。
- **原因**：保证日志不仅可查看，还能用于故障恢复、评测复核和状态一致性验证。

## ADR-012：公开历史不保留本地占位邮箱

- **状态**：已接受，推送前待执行
- **日期**：2026-08-03
- **决策**：当前本地提交使用 `wyd@localhost`，但首次公开推送前不保留该地址。取得用户确认的 Git 邮箱或 GitHub noreply 地址后，统一改写本地提交作者；提交哈希变化后同步更新所有记录和交付材料。未取得确认前禁止公开推送，不猜测用户邮箱。
- **原因**：避免作品集公开历史包含不可关联的占位身份，同时避免助手擅自写入错误个人信息。

## ADR-013：安全过滤不是产品消融变量

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：V0、V1、V2 全部强制启用 `AgentContextFilter`。“提示词保密 vs. 程序化过滤”仅作为离线 A4 安全消融，使用合成数据、禁用持久化和外部动作，并明确标记不可部署。
- **原因**：消融实验不能制造容易误部署或污染真实状态的不安全产品版本。

## ADR-014：V1 与 V2 使用不同复杂度的记忆检索

- **状态**：已接受
- **日期**：2026-08-03
- **决策**：V1 仅增加基础向量相似度 Top-K 长期记忆检索并保持固定课程；V2 才使用相关性、重要性、时间新近度等多因素记忆排序，同时加入自适应教学和 Reflection。
- **原因**：确保 V0→V1 主要测量基础长期记忆价值，V1→V2 再测量排序、教学适配和 Reflection 的联合增益。
