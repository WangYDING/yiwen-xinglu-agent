## 运行与预算准备

仅在新能力和 fixture 实现后给出真实命令，不能虚构 `--agent-condition A0` 等当前不存在的参数。旧 v2_regression_preflight READY 只覆盖旧场景，不能证明新设计 READY。

分池 G/C、M、R、S；每池硬上限和总和均待冻结，默认不互转。若用户选择拆分 G/C 预算，记录在最终 manifest。报价包含每回合初次/一次修复、源反思与 R 的初次/修复，用户模拟或 judge 若选用另计。参考旧实测可作区间估算，A0 和新任务未运行前不能宣称精确费用。

正式执行顺序：先 G 检查新接入是否引入阻断，再 C 与 M，RQ/S 按已授权清单执行。G 低完成率本身不是停止门槛；权限异常、证据缺失、环境不可用才暂停相关轨道。预算未知暂停核账，超限不启动新请求。保存已启动、未启动、停止原因和最终账本。

本设计不要求把所有 E 缺口修到通过后才能研究模型能力；但要完成整个 V2 覆盖交付，每项必需检查都需要实际可审核结果，未实现或未执行项目必须明确列入未完成清单。不能把声明边界写清楚等同于缺口已补齐。
